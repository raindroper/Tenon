# Windows 桌面客户端与本地执行

从 0.1.35 起，安装程序、快捷方式和托盘使用「榫 Tenon」和同一枚图标。原有登录、设备配对和项目记录继续使用原配置目录。旧客户端仍可通过「检查更新」升级。

桌面客户端加载与网页相同的 HTTPS 页面。服务端保持唯一 Mastra 运行时、任务许可和个人记忆；Windows 承担设备授权、受限执行、真实操作回执及 ChatGPT 登录的本机回调辅助。鸿蒙客户端按原生 ArkTS/ArkUI 方案调研，复用业务接口，不继承 Windows 本机能力，见[鸿蒙调研](harmonyos-client-research-2026-11-08.md)。

Windows 0.1.12+ 支持原生桌面通知与聊天窗口关闭后托盘接收，Web 支持浏览器通知。在设置中开启及测试，实际范围见[桌面通知](desktop-notifications.md)。

## 构建与运行

使用项目启动器选择 Node 24.22.1+：

```powershell
npm ci
npm run desktop:build
npm run desktop:start
npm run desktop:package
```

构建目录是 `.local/desktop-build`，安装包输出到 `.local/desktop-artifacts`，不纳入版本控制。发行包只包含客户端及已核验的执行资源，不打包服务端、用户数据、模型密钥或仓库 `.env`。独立发行须提供自己的服务入口、更新地址和签名公钥；未配置更新时保持更新关闭。

通用客户端首次启动时要求配置自己的 HTTPS 服务地址。服务端必须包含本次设备 API；仅安装客户端不会更新服务端。原有 HTTP+SSE 页面通信保持，新设备通道使用独立的 HTTPS Bearer 认证和 SSE，不需要 Windows 入站端口。

## 更新 Windows 客户端

通用源码不包含预设服务地址或发行更新渠道。未提供发行配置时，客户端要求手动连接，自动更新保持关闭。

独立发行时，在仓库之外创建私有 JSON，例如：

```json
{
  "appId": "org.example.assistant",
  "baseUrl": "https://assistant.example.com",
  "updates": null
}
```

将环境变量 `RAE_DESKTOP_PROFILE_FILE` 设置为该文件的绝对路径，再运行桌面构建或打包。`appId` 需为自己的稳定发行身份，`baseUrl` 为规范 HTTPS origin；空字符串表示首次启动时手动配置。该文件不会作为源文件提交，构建只将必要配置写入忽略目录中的发行产物。

需要更新时，将 `updates` 配置为含 `baseUrl` 和 `publicKey` 的对象。更新地址必须为规范 HTTPS URL 并以 `/` 结束；公钥为对应 Ed25519 公钥的规范 SPKI DER base64 编码。签名私钥独立保存，通过 `RAE_DESKTOP_UPDATE_KEY_FILE` 指定。未配置更新时，签名与发布操作应明确拒绝，不能绕过验签或回退到别人的更新站点。

从 v0.1.3 开始，任务栏托盘和本地设备窗口提供“检查更新”。找到新版后，点“下载并安装”。客户端核验发布清单签名和安装包哈希，等本机操作结束后启动安装程序。安装完成后重新打开 A‑R。已有设备连接信息随应用数据保留。

发布客户端时，先用 `npm run desktop:package` 生成安装包和 `latest.yml`，再用 `npm run desktop:sign-update` 生成 `manifest.json`。签名命令从 `RAE_DESKTOP_UPDATE_KEY_FILE` 读取发布密钥的绝对路径。客户端内置对应的 Ed25519 公钥。密钥保存在发布电脑的受限用户目录，发布到发行服务器的文件是版本化安装包、`latest.yml` 和已签名清单。

## ChatGPT 模型登录

0.1.25 或更新的客户端可为远程榫服务辅助完成 Sign in with ChatGPT（SIWC）。先将服务端和客户端更新到支持模型连接管理的版本，在客户端聊天窗口登录自己的榫服务，再打开「更多 → 设置与连接 → 模型连接」。

1. 点击「连接 ChatGPT 账号」，填写连接名称，选择「Continue with ChatGPT」。
2. 主进程临时监听本机回调并打开系统浏览器，由本人完成账号选择与授权。回调仅属于本次登录尝试；取消或关闭登录设置面板会请求取消，本机监听另有超时清理。网络中断时按实际回执核对服务端结果。
3. 一次性回调通过已登录的榫会话交给目标后端。后端校验、换取和加密保存 token，并负责后续续期；桌面页面、本机项目执行器及命令子进程不持有这些 token。
4. 登录完成后获取账号模型目录，再保存全局、后台默认或场景配置。添加第二个账号不会退出或覆盖第一个账号，也不会自动改变已有选择。

普通远程网页目前不能直接完成首次登录或重新授权，可管理和选用已经连接的账号；本机网页可使用自己的 loopback 回调。旧版桌面客户端没有这一辅助接口，需要升级客户端，不能只刷新远程网页。此流程使用榫自有授权，不读取 Codex CLI 的登录缓存。

登录和读取目录不启用推理，真实模型测试须本人明确点击。账号是否已登录、是否授权套餐调用、模型是否可用分别核对；离线协议与界面回归不代表已替本人完成 OAuth 或真实模型验收。连接失效及场景继承规则见[模型连接与默认配置](user-guide.md#模型连接与默认配置)。

## 连接设备

1. 打开 Windows 客户端，在聊天窗口登录。首次登录后，主进程使用该登录会话登记电脑并保存经 DPAPI 加密的设备凭据。
2. 在聊天窗口交代任务。Windows 客户端默认选本机。网页和其他电脑可以在对话中选择设备，也可以说出设备名。
3. 对话中已明确设备、目录和查询要求的本人委托，会登记一次许可并由原生执行器读取元数据，结果返回原对话；范围不清或由榫自主提议时再显示待确认任务卡。命令委托使用本次任务的临时空间，或在任务卡中列出实际文件夹和读写权限。已有旧版授权可在托盘查看或撤回。
4. 已知具体命令时，也可在“＋ → 明确委托”选择“在指定设备执行命令”。手动配对入口仍可在本地设备窗口展开。

带空格或边界容易混淆的目录可用引号包住完整绝对路径。明确要求整理、分组或判断清理候选时，许可同时记录这项只读分析。同一任务先保存原始文件列表，再用设备回执生成建议；只要求列表时，设备结果直接交付。随后在同一主题追问可读取原回执，无需再次扫描。整理失败时保留已返回的列表并标明未完成。文件名、大小和修改时间只能提供线索，清理建议不授权删除或移动。

配对和目录授权不等于任务许可。首版只接受明确委托中的那一条精确命令，不根据普通聊天关键词授权，也不给成长回合执行工具。已有推理启停设置保持；暂停时任务只保存。

v0.1.9 引入结构化的原生目录查询：`entryType=file` 查询顶层普通文件，`entryType=directory` 查询直接子文件夹，可指定名称过滤和条数。不会递归或跟随目录链接，也不读取文件正文。2026-11-07 内核升级源码将明确查询委托纳入统一 `request_task`，无需对同一范围重复批准；斜杠、目录名或目标设备有歧义时先询问或提案，不按句子模板授予访问权。部署版本须另行核对。

对话工具不再提供程序路径、脚本参数或 `run_local_command`。文件和项目定位不会再由模型临时拼 shell。原生查询与本人在“明确委托”入口手工指定的精确命令，共用许可、设备执行和回执通道；后台任务工作流分发原生操作，等待结果时前台仍能交流。只查询列表或运行精确命令不会增加模型调用；委托已包含目录分析或文本交付时，收到真实结果后继续处理，无需逐步再批准。任意程序仍受 MXC 的实际隔离边界约束，错误按真实退出码和标准错误显示，不以程序名黑名单代替执行能力，也不猜测宿主账户权限。

旧版模型生成的命令提案保留为只读历史，不能再批准。旧版尚未发到设备的隐式目录许可会在启动时撤销并保留原因；已人工批准的任务和已经实际下发的操作保留原范围，不重放、不改写回执。

标准输出和标准错误先按原始字节限量保存，待进程和输出流结束后解码，支持 UTF-8、带 BOM 的 Unicode 和本机 Windows 控制台代码页。匹配任务许可的失败回执会显示实际退出码和标准错误；缺少执行记录或许可不匹配另行说明。已有失败历史保持原样，不自动重跑。

v0.1.10 由同一个回执交付组件处理正常结束、迟到回执和服务重启后的补偿。它核对原任务、批准版本、精确范围和运行事件，仅更新已有任务结果，不生成新许可或重排执行。迟到成功会补回一条固定编号的结果消息并更新任务/运行状态，原中断正文与先前错误保留；重复上传或再次重启不会重复交付。任务已撤销或主题已停止时不恢复执行权；只完成目录读取也不会把尚未完成的模型分析记成完成。暂停推理时仍可保存并交付已有设备回执，不调用模型。

本机进程重启后，未完成的原生只读查询明确结束为失败，保存原中断状态并允许新的明确查询；旧查询不自动重做。旧版本遗留的同类 `unknown` 记录按相同规则迁移。任意程序即使带只读文件授权，也可能有其他副作用，其结果未知时仍保留执行停止保护。查找旧结果时跳过后续失败任务，按实际成功回执时间选择；明确回复某一任务时只读取那项任务，不用其他设备或任务的结果替代。

## 微信会话观察

在已登录官方微信并登记榫设备的 Windows 电脑上，打开「更多 → 设置与连接 → 微信观察 → 打开微信观察设置」，也可从托盘「本地设备与授权」进入。点击「查找会话」，按群名、联系人名或关键词筛选，勾选会话后绑定一个榫主题。每台电脑最多保存五个会话。同名会话显示原名和最近活动时间供核对。勾选并保存「榫启动时自动观察」后，客户端会在本次和后续启动时尝试观察已保存的会话。

当前支持经过核验的 Windows 微信 4.1.15.56 构建。客户端从已登录微信进程获取只读访问本机加密数据库所需的密钥，以账号和会话标识核对范围。微信保持登录并同步时，最小化和锁屏期间都可尝试读取已写入本机的新文字。切换账号时需要重新选择。升级前保存的窗口选择会保留名称和主题，需移除旧条目并重新选择才能启动后台观察。

客户端仅向已配置的榫服务发送所选会话的记录。v0.1.7 将读取位置、待确认批次和最近接收样本通过 Windows 安全存储加密保存，服务端确认后再提交进度。断网、客户端重启和更新后从保存的进度继续，跨授权续期和重新登记保持去重。数据库读取密钥只在进程内存中使用。

首次添加默认从现在开始，可选择最近 24 小时或指定历史时段。已保存会话也可补采指定历史，保持原会话绑定和去重。只读取本机实际存在的记录；指定历史终点到实时采集起点之间的空档不会被描述为连续覆盖。旧版本没有保存断点，升级首次启动会明确显示新的覆盖起点，需要较早消息时使用补采。

每个会话可独立暂停、继续并补采、从现在重新开始或立即同步。暂停后继续是否读取暂停期间消息，由所选恢复操作决定。界面显示接收记录数、待上传片段、最近接收时间、覆盖起点、最近原文和分析状态。非文字消息记录类型占位，长文字分段保留；逻辑消息与片段计数分别展示。来源保留群名、可核验的发送人、原始时间和本人标记，无法核验的字段保持未知。

从 v0.1.6 开始，微信读取排队时各会话仍会独立发送心跳。网络中断或榫重启时，会话显示「正在重连」。客户端保留读取位置和待确认的批次，连接恢复后继续采集。租约过期时使用本人登录续期同一授权，服务端沿用原来的消息去重记录。已停止或撤销的授权不会通过续期恢复。

微信消息默认每十分钟合并进入分析，也可为会话设置频率或立即分析。积压内容按完整的有界页面依次处理，保存每条记录的批次归属和实际分析状态。失败批次显示未完成，由本人恢复；同一批次重试更新原通知。没有新内容时不调用模型。暂停推理仍可接收消息，已接收、待分析和已分析分别显示。

在普通聊天里按群名、时间、发送人或关键词查询，直接读取当前主题已接收的消息，不必等待自动分析。结果附原始消息依据和实际覆盖信息。其他主题只提供会话名称及主题切换线索，正文仍限所属主题。旧记录只在同设备、同保存会话绑定再次登记后补上名称，旧记录缺少发送时间或发送人时不能猜测。

榫可归纳决定、时间变化和待办，任务提案引用原消息。执行产出文件或代表本人操作前沿用现有本人任务许可；群内消息不能成为执行授权。撤销会话或设备后，相关来源和未执行提案停止使用，已保存数据保留供导出追溯。

## 执行与结果

命令绑定设备、本次文件范围、执行程序、按顺序保存的参数和超时。服务端 派发前检查许可。Windows 核对实际目录与程序身份，并在原生启动前再次向 服务端 请求单次准入。断线期间不能开始新操作，所有等待和执行沿用原轮次五分钟上限。

本地采用固定 `@microsoft/mxc-sdk@1.0.1` 的 ProcessContainer。要求原生 BaseContainer 和路径枚举能力；禁止网络、剪贴板及 UI 输入注入。严格探测不通过时显示不可用，不自动改成普通用户无限制执行，也不自动进行 DACL 降级。Windows 更新/组件要求以实际运行时探测为准。

本地先持久保存操作编号，再启动进程。相同编号不重复执行；服务器和本机重启后先将没有结束回执的旧操作标记未知，仅核对原结果。退出码、输出和错误可在“我的设备”查看；程序退出码零只能证明命令执行成功，业务产物仍需按任务验收。

停止通过 MXC 请求终止，再等待原生执行与输出流结束。取消请求、许可撤销与实际停止是不同事实；失联或没有终态回执时明确报告未知，不声称已经全部停止。晚到回执更新原操作，不自动恢复模型回合或重复命令。

回执先写入本机日志，提交失败后在正常心跳或重连时补传。设备已撤销时，旧凭据只可补传原操作的终态回执。历史未知结果保留在原操作，后续无关的设置和记忆编辑可继续。

升级时复核从旧版聊天直接取得、尚未派发的目录查询许可。无法从原消息核对完整范围时撤回许可，保留原任务和事件，并在卡片提示重新委托。已经派发的设备操作继续按原回执核对。

## 数据与退出

服务端的配对哈希、设备记录和操作日志存入既有 `v2-events.sqlite`；模型密钥和 SIWC token 不下发。设备状态/心跳/结果不进入待推理队列。JSON 导出包含设备与操作记录，不含配对码或设备凭据；备份仍是整个服务数据目录。

本机设置和操作日志存于 Electron `userData`。关闭窗口后托盘继续持有本地进程；从本地控制暂停，或从托盘退出，会先排空原生操作。电脑睡眠/关机时本地能力不可用，服务端 云端既有交流和安排不随客户端关闭。

首版没有通用鼠标键盘/任意应用控制，没有本地模型，也没有在鸿蒙运行 Windows 命令。桌面 GUI 工具将另按具体任务选型，不与 MXC 命令隔离混成一项权限。

## 服务更新与回滚

设备表为追加迁移，旧消息、任务、许可与用量不改写。上线前按项目契约完成 `npm test`、`npm run check`、`npm run build`，并保留旧发布及完整数据备份。Linux 服务不会加载桌面 MXC，依旧只运行一套 Mastra；Hub 无须改动。

回滚须遵循[当前内核迁移契约](kernel-upgrade-2026-11-07.md#7-数据迁移与回滚)：不能仅切换旧应用代码后继续读写升级后的数据库。先保全升级后新增的消息、回执与产物，再恢复对应代码版本的成套数据备份，或采用经过验证的兼容迁移。不能确认兼容时保持暂停和可读/导出，不强行启动旧执行器；不得删除设备记录或重复提交未知操作。撤销设备不等于删除历史。测试只使用隔离目录和离线模型，不自动启用真实推理。
