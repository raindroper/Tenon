# 桌面通知

Web 与 Windows 0.1.12+ 在「更多 → 设置与连接 → 桌面通知」开启；浏览器还需在系统弹窗允许网站通知。可发送测试通知，无需模型调用。默认只显示事件类型，勾选显示摘要后才在系统通知中展示消息或任务标题。偏好仅保存在当前浏览器/客户端，互不强制同步。

通知覆盖所有场景的新回复、日常提醒、未完成回复、任务完成/失败和待确认提案。点击后回到对应场景最新对话。正在生成的文字和 prepared 交付物不代表完成，不触发完成通知。同场景同批更新合并；同一浏览器的多个标签页通过 Web Locks 与仅含事件 ID 的有限本地记录去重。浏览器与客户端是独立通知入口，同时开启可能分别通知。

榫的 Windows 聊天窗口在前台并拥有焦点时，自动更新只通过未读角标提示。需要检查系统通知时仍可手动发送测试通知。场景标签用红点提示未读更新，折叠的场景也会在「更多」里标出。Windows 0.1.21 起，任务栏图标显示有未读更新的场景数，数字最多显示 99。最小化时仍可在任务栏看到角标，关闭窗口到托盘后，恢复窗口时可再次看到。切到该场景的最新对话且窗口有焦点时，清除该场景的未读。角标独立于桌面弹窗设置，只记录本次页面会话的新更新。

首个登录快照仅建立基线，不补弹历史通知；切换场景或翻阅历史不改变通知范围。实时重连用结果 ID 去重。当前摘要覆盖最近一百条消息中的助手消息，不是永久可靠的离线推送队列；长时间断开后的通知可能不齐，全部正文仍保存在对话中。退出登录、关闭通知时清理待发通知；旧点击回调失效。

网页需要保留标签页，完全关闭页面后不支持推送。Windows 客户端关闭聊天窗口会隐藏到托盘，托盘「打开榫」或点击通知可恢复窗口；托盘「退出」仍按既有规则排空设备操作后退出。休眠、离线、客户端完全退出、浏览器休眠标签页以及 Windows 勿扰/通知限制都会影响到达或横幅显示；系统不一定提供准确的送达确认。没有新增服务、模型轮询或开机自启动。

服务端在现有 RuntimeView / SSE 中增加可选 `notificationMessages`，只读投影已保存的公开消息 ID、场景、时间、最多 160 字预览和输出状态；不建立通知业务数据库，不修改历史消息、任务许可或执行路径。Windows 使用 Electron 原生 Notification，进程间通信仅接受配置 HTTPS 来源的主窗口和有界字段，不能传入任意 URL、文件或执行指令。浏览器权限没有扩大为剪贴板读取或本机能力。

回归覆盖旧历史不重播、流式完成、跨场景、失败与提案、准备态不误报、多标签页抢占、等待时退出登录、原生点击失效、摘要边界以及真实 HTTP/SSE 全局通知与分场景正文并存。实际系统显示另以离线合成通知验证，不向日常会话写测试消息。

2026-11-08 验证：全量离线 664 项通过，通知投影后续专项 9 项通过，类型与构建通过；Windows NSIS 0.1.12 打包及既有 Ed25519 更新清单签名通过，发行 Python/SQLCipher 12 项通过。Electron 45.2.2 中加载实际构建页面，Windows 原生通知返回 show 事件，隐藏窗口仍收到跨场景完成通知，点击处理回到对应场景；同一浏览器存储分区的两个页面只发送一次，关闭通知后不再发送。点击验收通过原生 click 事件模拟，不代表已检验每一种 Windows 横幅/通知中心交互。系统勿扰可继续限制实际横幅显示。
