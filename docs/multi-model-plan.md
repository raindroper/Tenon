# 模型连接与受控分派

本文件讨论模型接入的工程边界，不列出维护者的账号、订阅、服务器、模型池或调用记录。当前产品行为以 README 与运行时代码为准；尚未实现的自动多模型分派不作为现有能力宣传。

多连接、多账号、全局与后台默认、场景覆盖和失效处理见[多模型连接与配置需求及实现方案](model-connections-2026-11-14.md)，其中第 18 节记录 0.1.25 的实现与验证。自动分派和自动跨连接回退不在本期范围内。

## 配置边界

- 每个部署者自行配置服务地址、密钥与模型标识。目录中的展示名不能直接作为可调用的 API ID。
- 统一兼容接口不表示工具调用、流式、图片、推理参数与上下文行为相同。适配器须以实际供应商协议验证。
- 模型连接只提供推理能力，不产生任务同意或扩大资料访问。个人理解、方法记忆、授权与操作回执仍由唯一运行时负责。
- 输出上限是可选连接设置；未设置时沿用供应商默认值。只保存供应商实际 token，用量缺失或部分报告保持显式状态，不计算价格或积分。

## 网关接入

若使用外部兼容网关，通过其支持的 HTTP 与配置接口连接。凭据保存在部署者的私有配置中，不从账号备份文件共享运行时令牌，不修改网关私有模块。

服务端与网关分别设置进程、网络、日志和数据边界。反向代理的地址、证书与容量由部署者决定，通用发布流程见[部署说明](deployment.md)。

## 分派与恢复的设计要求

未来分派能力必须沿用已有任务准入、同意与资源检查。模型失败、权限不足、限流或数据不可用不得通过更换模型扩大读取范围或重复外部操作。恢复保留原任务身份、要求版本、步数、期限和已接受操作回执。

新增模型适配应优先替换现有接入中的具体缺口，不引入第二套代理循环或竞争的任务状态。仅有模型目录项和一次成功答复，不足以证明复杂任务、长上下文、图片或工具兼容。

## 验证

使用隔离数据与脚本化供应商验证请求参数、流式终止、工具协议、取消、重试、用量和未知结果。真实模型验证需要明确授权，并将私人输入与调用回执保留在公开仓库之外。
