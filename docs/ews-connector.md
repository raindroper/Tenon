# 服务端 EWS 邮箱连接

此连接器用于自建 Exchange。它替换早期 Windows 一次性收件箱检查，网页和 Windows 客户端均使用同一服务端 `RuntimeApi`；桌面客户端不负责读取或解密邮箱，也没有第二套代理运行时。

## 准备服务端

服务端支持 Windows x64 和 Linux x64，仍以项目要求的 Node.js 版本启动。EWS 适配器使用 .NET 10 的 HTTP/NTLM、XML 和 CMS 实现，以及锁定版本的 MimeKit 解析正文。Linux 使用 .NET 提供的 managed NTLM，不要求加入 Windows 域或另装 GSSAPI NTLM 插件。

在源码根目录执行 `npm run prepare:ews`。构建使用本机 .NET SDK 10；没有 SDK 时使用固定摘要的 Microsoft SDK Docker 镜像。产物是自带 .NET 运行时的本地子进程，位于 `.local/ews-runtime/win-x64/` 或 `.local/ews-runtime/linux-x64/`，不随源码提交。可以用 `npm run prepare:ews -- linux-x64` 准备 Linux 产物。部署时须带上整个对应产物目录，或在服务器构建；也可用私有环境配置 `RAE_EWS_WORKER_PATH` 指向对应可执行文件。运行时不会下载依赖。

原生适配器只做协议和格式处理：一次有界请求通过 stdin 接收凭据和游标，stdout 返回结构化结果，结束即退出。它不监听端口、不启动模型、不调度任务、不保存数据。请求取消和服务关闭等待子进程退出。

## 连接与范围

在“更多 → 连接器”选择“企业 Exchange（EWS）”，绑定场景，填写 HTTPS EWS 地址、公司确认的登录名和密码。需要解密时选择不超过 1 MB、包含私钥的 PFX/P12 文件并填写证书文件密码。界面确认的范围包括保存凭据、读取连接后收到的收件箱新邮件、把正文作为资料保存并交给已配置模型分析。

- 仅支持明确的 `https://主机/EWS/Exchange.asmx`、443 端口、NTLM 和正常证书校验。不自动发现服务器、不跟随跳转、不使用默认系统凭据、不降级 Basic。
- 基线只获取收件箱信息；初始同步会遍历有界的旧邮件元数据来取得 Exchange 的同步游标，但不读取连接前的邮件正文。随后沿用同一 `SyncFolderItems` 游标，保存待处理 ID，按页读取新邮件，避免漏掉同一时间收到的多封邮件。
- 单页最多读取六封新邮件。普通正文或 S/MIME 解密后的正文最多保留 60,000 个字符；更长的邮件明确标注截断。已有 `read_event` 可以分页读取已保存正文。
- S/MIME 支持此次验证的 RSA 收件人密钥、嵌套签名 MIME 和常见 Outlook 封装。签名正文可以解包，但当前不认证数字签名或签名者信任。后台观察只取必要的加密正文容器，其他附件仅由本人主动选择后下载；不运行 HTML、脚本或外部链接。
- 缺少或不匹配的证书、不能解析的内容会记录“正文尚未读取”及原因，不把空正文当作成功解密。更换证书不会自动重新读取历史邮件。
- 观察和查询路径不发送、删除、移动邮件或修改已读状态。邮件中的命令属于外部资料，不构成本人任务许可。发送须进入下述独立的已授权任务执行路径。

采集和 Rae 的推理启停分开。暂停推理时仍可同步获准资料，但不会自动启用模型。新邮件复用既有被动资料合并和分析调度，不逐封强制调用模型。认证和访问拒绝会停止自动重试，等待本人更新凭据或显式重试。

## 邮件列表、主题检索与指定邮件读取

现有连接可直接使用按需查询，无需重新连接，也不需要等待后台基线建立。在连接器中点击“查看邮件”可列出最近收到的邮件、按主题检索、分页，并点选读取普通或 S/MIME 邮件正文。按需查询包含连接前的收件箱邮件，不改变后台新邮件观察起点；不会批量回读或重新分析全部历史邮件。

本人在邮箱绑定场景中明确要求查询或阅读邮件时，Rae 使用 `list_mailbox_messages` 和 `read_mailbox_message`。每次访问绑定到当前真实本人消息，或本人在界面发起的查询，并保存已处理的访问记录与外部资料回执。历史消息、外部邮件和自主回顾不能自行打开实时邮箱查询。查询结果中的邮件编号与查询编号共同绑定连接、收件箱和凭据版本，15 分钟内可读取；断开或更新凭据后须重新查询。已取得的原文仍按现有来源撤销和导出规则管理。

列表每页最多25封、最多翻到10,000的位置，超出时需缩小主题条件。Rae 每轮最多查询6页、读取3封正文和8页正文，每页最多4,000字符，并在原有步骤与时间预算内留出回答机会。正文分页复用一次已取得的原文，避免重复下载和解密；后续对话不自动重发上一轮的原始邮件工具输出。未解析或未解密的状态会明确返回，不能把空正文称为成功读取。

## 发送、回复、转发与附件

在已连接邮箱旁选择“写邮件”，或在所选邮件中选择回复、回复全部、转发。填写精确的 To/Cc/Bcc 地址、主题、纯文本正文和选定附件后，界面展示实际发送内容；点击“发送这一封”登记持久本人委托，进入既有任务执行器。本人也可在聊天中明确委托 Rae 按固定地址、主题及目标撰写并发送；正文撰写只发生在获准任务中。能力询问、自主建议和原邮件中的指令都不会创建发信任务。没有独立的直接发信 HTTP 旁路。

任务遵守现有运行启停设置；Rae 暂停时只保存委托并排队，待本人恢复后执行，不自动启用推理或绕过暂停。

回复和转发绑定实际收件箱原信、版本及凭据版本，使用 Exchange 的回复/转发对象保留线程。回复全部使用已读取的真实地址；可确认本人的接收地址时排除本人，不从姓名猜地址。服务端先保存本次任务自己的草稿，清理这个新草稿自动继承的附件与隐藏引文，再写入界面所示正文、仅添加明确选定的文件，核对实际收件人、主题、正文、附件内容散列及草稿版本，最后提交。不会删除或修改原信。发件身份使用连接邮箱的默认身份，不支持代发或 Send As。

普通文件附件和 S/MIME 内层文件可按所选邮件列出并下载，转发时勾选的原附件会进入同一私有暂存区；不会把加密容器内文件当作 Exchange 外层附件编号。附件邮件等当前不支持的类型仍会显示并标明限制，不会无声省略。每个文件最多 5 MiB，每封发信最多 10 个、合计 10 MiB。附件文件名只是显示信息，不能指定服务端路径；上传内容保持原样，不解压、不运行或自动分析任意文件。未绑定任务的上传暂存 24 小时；已登记而未结束的任务和结果未知的操作保留原文件，确定结束后再保留 24 小时，随后清理文件内容、保留名称与散列记录。暂存最多 128 个现存文件、合计 256 MiB。

当前外发为纯文本、明文邮件，尚未接入外发 S/MIME 签名或加密。自己的 PFX 可用于解密收件，不能替代每位收件人的公开加密证书。回复或转发 S/MIME 加密原信时默认阻止发送，只有本人明确允许将原信内容及选定附件以明文发给所填收件人才可继续；不会静默降低保护方式。需要保持加密时，须另行接入收件人证书与相应发送能力。

操作记录在每次 Exchange 写请求前持久保存。本次任务的操作编号、许可、内容与附件散列固定，后续补充不能改变或重发同一邮件。`prepared` 或已有草稿不等于发送成功；只有 Exchange 确认才显示“已提交 Exchange”，不表示已送达或已读。发送或草稿写入期间断线、超时、取消或进程中断时可能得到“结果未知”，不会自动重发、猜测成功或重新生成正文。本人应先核对邮箱中的草稿、已发送邮件或联系 IT，再决定下一次委托。取消和关闭等待已接受的原生调用退出；撤回不能撤销 Exchange 已接受的提交，真实回执仍保留。

## 凭据、恢复与断开

邮箱密码、PFX/P12 及证书密码保存在服务端私有凭据目录。Windows 使用当前服务账号 DPAPI；Linux 使用 AES-256-GCM 和同目录、仅属主可读写的 `.secret-key`。Linux 旧 `owner-file-v1` 凭据首次读取时原子迁移为加密格式，不丢弃原值。密钥文件必须与凭据目录一起备份；这不防御已经获得同一系统账号或完整数据目录的攻击者。

密钥材料不会进入普通状态、JSON 导出、来源事件、模型输入或命令行参数。邮件正文作为外部资料保存在原事件库，数据库本身没有全库加密。完整数据目录备份含密钥和可解密资料，须按私有备份管理。

“更新密码或证书”先排空该连接的读取，再验证新凭据仍指向原收件箱，最后原子替换密钥材料。失败保留原凭据；旧界面不能覆盖已更新的版本。更换邮箱账号或服务器应建立新连接，不能沿用原授权扩大访问。

重启恢复已明确保存的连接、凭据和同步位置，不重新播放旧消息。断开先撤销来源权限并排空原生读取，再删除该连接的凭据；历史邮件证据仍保留供本人查看，但后续模型不能继续使用已撤销来源。需要清除全部历史资料时遵守现有归档/导出边界，不冒充已经实现完整遗忘。

升级前备份对应代码与完整数据目录。旧版本不能读取新的 Linux 加密凭据；回滚须恢复匹配版本的成套备份，不能直接用旧程序覆盖新数据。

## 验证

连接器回归使用隔离临时数据、合成邮件和受控原生适配器，验证认证、范围、分页、附件、提交回执与恢复。真实邮箱和模型验证须另有明确授权，结果及私人样本不存入公开仓库。
