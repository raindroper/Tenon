## 三分钟持续负载

可重跑命令：

```powershell
$env:NODE_OPTIONS='--max-old-space-size=512'
npm run test:stability
```

脚本位于 `tests/stability/soak.test.ts`，不加入日常根目录测试通配符。默认 180 秒；`RAE_STABILITY_DURATION_MS` 可选 3000–900000 毫秒，较短值用于验证夹具，不能当作长期结果。

本次实际负载持续 180,675 ms，使用 512 MiB V8 堆限制、真实本机 HTTP/SSE、SQLite 与 Mastra，模型由内存 Mock 提供，外部模型请求为 0：

| 指标 | 结果 |
| --- | --- |
| 预置历史 | 10,000 条事件、2,000 条运行记录 |
| 接收唯一消息 | 358 条，每条并发发送两次，共 716 次 POST |
| 模拟模型调用 | 358 次，与唯一消息数一致，没有因重发或重启重复处理 |
| 重启 | 2 次关闭运行时及数据库后重开，复用原数据 |
| SSE | 快速与较慢消费者并存；25 次主动断线重连；验证增量基准连续和主题隔离 |
| 当前状态体积 | 约 45.7–85.4 kB，始终低于 256 KiB 测试界限 |
| 采样快照耗时 | 约 1.7–6.9 ms；为本机观测值，不设脆弱的硬耗时断言 |
| 采样进程 RSS | 约 466–505 MB，随 GC 波动；没有在此窗口观察到持续单调增长 |
| 导出 | 358 条本人消息与回复全部保留；运行 2358 条、事件 10358 条全部保留 |
| 数据库 | 三个数据库 `PRAGMA quick_check` 均为 `ok` |

这是持续数分钟的有界稳定性验证，不是 24 小时或生产流量压测。50,000 / 5,000 规模回归另外验证了每次历史查询返回行数、索引选择及完整导出，不以大数据快照测量冒充长期负载。

## 数据与兼容边界

- `rae.sqlite` 新增 `owner_message_requests` 和查询索引；设置启停版本保存在 metadata，与启停值原子更新。旧消息和配置不改写，完整数据目录备份仍为恢复方式。
- 当前前端发送稳定请求 ID；无 ID 的旧消息 API 继续作为独立提交处理，不承诺旧客户端的网络重试幂等。
- `/api/settings` 修改 `enabled` 需 `expectedEnabledRevision`。旧全量设置表单会收到 409，须刷新页面；明确启停仍可用 `/api/control`。
- GitHub 新版本接受旧游标。2026-11-07 已检查上一线上版本的非严格游标解析：忽略新增分页字段但保留原 `at/numbers` 下界，能从旧窗口重读，不会把尚未完成的分页当成已完成；旧同秒批量推进问题仍可能复现。发布时线上没有 GitHub 连接，未进行真实 GitHub 游标迁移或生产回滚演练。
- `not_used` 仅用于新代码能证明未调用模型的回合；旧缺失记录仍为未知。旧版前端可能将新状态显示为不完整，因此服务端与前端应作为同一发布快照。
- GitHub HTTP 接口不是快照或完整事件日志，不承诺捕获每个瞬时中间版本。11 月 6 日离线验证未连接真实 GitHub、微信进程、模型或媒体上游；11 月 7 日发布仅额外只读查询了上述既有 Hub 视频任务，没有重新生成。
- 运行/事件历史已分页；任务、成果、个人理解等其他集合没有在本轮改成分页，不据此宣称所有数据量都无限可扩展。

本轮仅新增必要表、索引、协议字段、回归和验证脚本，替换旧表单覆盖、无标识消息发送、GitHub 游标推进、微信候选集验证及全量历史快照路径；没有清除用户历史或引入第二套运行时。
