# 自托管部署与回滚

本文使用通用示例，不提供维护者的服务器、账号或发行渠道。部署时填写自己的域名、私有配置路径与发布标识；不要把实际值提交到仓库。

## 配置与数据归属

- 运行环境要求 Node.js 24.22.1 或更新版本。依赖和原生资源按锁文件及构建脚本核验。
- `RAE_DATA_DIR` 指向持久数据目录；生产目录与源码、构建输出分别存放。
- 公网部署必须设置规范 HTTPS origin，例如 `https://assistant.example.com`，并通过 `RAE_AUTH_FILE` 配置内置用户。凭据文件不放在静态资源目录中。
- 模型、连接器、设备和发行签名凭据使用各自的私有存储；日志、备份与导出也按私人资料管理。
- 使用 `ops/` 中的部署样例时，先替换域名、路径及镜像选择，并检查有效 UID/GID、挂载、网络和权限。

后端只运行一个拥有数据租约的生产实例。反向代理回源宿主回环端口；容器内部监听、宿主端口发布和公网入口分别验证。启停设置与数据迁移不通过构建脚本自动改变。

## 发布流程

1. 冻结一份源码与构建产物，按修改范围运行测试、类型检查和构建。核心运行时、存储、权限与模型循环修改需要完整验证。
2. 在独立数据目录或隔离容器验证候选。推理默认暂停，验收使用模拟模型及合成资料；不要挂载生产凭据或任务 journal。
3. 记录当前镜像、静态入口、worker、桌面更新指针和推理开关版本，核对没有需要保留的活跃操作。
4. 暂停并排空运行时，停止唯一生产进程，确认租约已释放。备份完整数据、私有文件、工作进程 journal 和匹配配置，并校验备份摘要与数据库完整性。
5. 以原值为前置条件切换到新版本。依赖未变化时复用不可变依赖；纯前端发布只追加哈希资源并原子切换入口。
6. 验证健康、匿名拒绝、本人登录、SSE 状态与心跳、设备实际能力以及既有数据标识。只有核验通过后，才按准确版本恢复切换前的推理意图。

榫的 HTTP 入口与本机模型转发不额外设置请求体字节上限。上游服务、业务字段、图片和附件的有效性规则仍然适用；服务器容量和单次请求超时也需纳入部署评估。

## Linux 执行设备

Linux worker 使用独立身份、凭据、journal 和临时工作区。设备凭据只适用于既定执行协议，不赋予网页用户权限。保留现有网络命名空间、文件系统隔离、cgroup、seccomp 与 AppArmor 配置；升级时重新验证实际限制和排空，而不只检查容器进程是否存活。

验收容器使用独立 journal 和合成任务。运行时不得自行下载或安装新的执行引擎、插件或技能。具体任务仍由单一任务准入与授权检查处理。

## Windows 发行

发行配置应显式提供自己的服务入口、更新地址与更新签名公钥。没有有效发行配置时，不应回退到其他人的下载渠道或绕过签名检查。

发布安装包前核对版本、文件大小、摘要和签名清单。保留旧版本安装包及更新指针，更新目录中的私人签名密钥不得上传。平台原生代码签名与应用更新清单验签是不同机制，不能混称。

## 回滚

先暂停并排空，保全切换后的新增数据，再恢复匹配的版本指针和配置。数据库版本发生变化时，只能使用经过验证的兼容迁移或与旧版本对应的成套备份；不能直接让旧二进制写入新数据，也不能未经保全就用旧备份覆盖新增资料。

回滚时同步处理网页入口、应用、worker 和桌面更新渠道，并重复必要的健康与鉴权检查。完整数据迁移边界见[内核契约](kernel-upgrade-2026-11-07.md#7-数据迁移与回滚)。
