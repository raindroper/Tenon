# 项目任务的文件交付

0.1.34 将 Windows 最终成果接入已有的保存与下载通道，并允许检查引用独立的辅助验证文件。检查复用、三类真实模型试跑与剩余限制见[检查与交付验收](delivery-optimization-2026-11-18.md)。

Windows 新任务只冻结已经通过检查的最终成果清单，快照与任务版本、检查证据及实际文件哈希绑定。后续源文件修改不会改变已经冻结的副本。上传完整并核对通过后，任务才能完成交付，文件可逐个下载或由服务端打包为 ZIP。无文件的操作任务继续按其实际回执完成。

辅助校验报告和原始输入可由检查明确引用，沿原文件范围读取并记录内容指纹。检查复用同时核对这些依赖，依赖改变会使相关检查失效。此类文件独立于最终成果清单，新的 Linux 归档传输也排除这些明确的验证依赖。

服务器任务的文件必须能由本人领取。执行器中的文件路径、模型说已保存、代码差异或临时工作区检查点，都不能单独代替文件交付。

## 一条交付路径

新服务器任务沿用原 TaskConsent、Mastra TaskExecutor 和设备协议。原生执行结束并排空后，执行端先保留匹配的持久检查点；任务执行器通过同一设备通道读取该检查点中的成果。文件分片进入主服务，逐项核对大小和 SHA-256，整批完整后发布清单。只有完成这一步，任务才能完成交付或进入本人验收。

运行检查点负责原生会话恢复；已发布的文件结果负责用户领取。它们是不同生命周期的数据，不是两套执行路径。验收后可以释放工作区和原生会话，文件仍从已发布结果下载，不再依赖执行端在线，也不触发模型或重跑任务。

文件结果由 `project_file_deliveries` 和 `project_file_chunks` 唯一写入。项目操作中的文件信息是读取投影，不另存可写清单。现有事件库新增这两张表，初始化可重复执行；不改写旧任务、许可、要求版本或原事件，内核版本8数据仍兼容。完整数据库备份包含文件内容；运行时导出包含结果清单，文件可单独下载或打包领取。

## 读取和发布边界

- 只读取原任务检查点中 `workspace`、`temporary`、`outputs` 的普通文件。原生执行器目录、`.git`、`.codex`、`.agents`、`.aws` 不进入成果包；不跟随符号链接或硬链接。
- 请求绑定任务、操作、设备、批准版本、要求版本、资源快照及检查点哈希。每次传输和最后发布均复核当前状态。更新要求、撤销许可、设备撤销或检查点变更会阻止未完成结果发布。
- 以256KiB分片传输，每批最多4096个文件，总量不超过原工作区容量许可。重复分片必须内容一致；中断时未完成清单不可下载，重试复用原检查点及已保存分片。
- 未保存文件时不会因计算已结束而自动删除唯一工作区副本。文件领取失败后可重试，沿既有原生回执恢复任务结果，不重新执行代码或调用模型。明确撤销、放弃或释放工作区仍遵循原控制路径。
- 文件接口要求本人登录。下载明确指定所属任务与不可变交付ID，返回附件而非在应用域内执行HTML。已交付文件是本人历史数据，读取它不重新开放已撤销的执行或连接器权限。
- ZIP 使用仓库原有的 [ADM-ZIP](https://github.com/cthackers/adm-zip) 0.6.1，并将它声明为直接依赖；没有引入另一个服务或压缩实现。

## 旧数据

仍保留检查点的旧服务器任务可以在任务卡点击“领取文件”，使用同一文件协议保存已有成果，不重启原任务。旧任务验收前也先保存现存文件，再释放工作区。升级不会主动复活历史任务或扩大旧资源许可。

旧版本已经释放的工作区无法从不存在的文件恢复。有此前留存且校验过的导出副本时，可以做明确记录来源的一次性数据恢复，写入同一个成果存储；文件仍绑定原任务和原要求，不能伪称执行端归档仍在，也不能伪造重新执行。未留存的文件不补造。既有文字、代码差异、操作回执和已保存历史继续保留。

## 验证

离线验证覆盖真实归档分片、中文文件名、空文件和二进制文件，ZIP和单文件下载、断传幂等重试、原任务结果恢复、许可及版本撤销、链接逃逸、篡改检测。完整HTTP流程验证：发布前不能完成任务；匿名和跨任务请求被拒绝；验收释放工作区后仍可下载；服务重启、执行端离线且推理暂停时仍可下载，模型调用数不增加。

任务卡沿用现有界面，提供文件清单、大小、单文件与ZIP下载。桌面及390px宽度的浏览器交互验证通过，无横向溢出；文件名及下载目标经过实际点击检查。

## 2026-11-16 发布及真实验证

服务端、执行端与网页界面使用同一快照更新；沿用现有依赖与原生执行引擎，Windows更新渠道未改变。完整离线回归1,224项、类型检查和构建通过，Linux候选38项检查通过。真实数据副本的新增表初始化和历史文件恢复均演练两次，确认幂等、没有新执行。正式切换保留备份和兼容回滚路径，已核对原有事件、项目操作、邮件操作、任务和问题记录，结果与备份一致。

- 在推理暂停时，通过已登录产品API领取原P10的3个实际文件，SHA-256与此前独立归档一致；原生会话及14次模型调用保持不变，最终验收仍待本人决定。
- 新合成任务实际生成并校验报告、JSON和检查回执。文件自动持久保存后才进入验收；验收释放工作区后、服务再次重启且推理暂停时，单文件及ZIP下载仍成功。原生模型调用数始终为4，JSON内容及所有文件哈希一致。
- 对账及缺陷演练的旧工作区在旧版本验收后已经释放。以此前留存的两份验证导出及原任务/检查点身份为依据，各恢复9个已校验文件到同一成果存储，标明恢复来源；文件从产品接口再次下载并逐项校验一致，没有重跑原任务或改写原验收记录。
- 实取归档发现内置Linux执行器的空锁文件，统一在生产、读取和打包边界排除该运行目录；保留历史原回执，不把运行元数据展示为成果。
- 线上匿名下载返回401，错误任务与交付ID组合返回404。原有六个连接与设置保持不变，维护结束恢复原先已开启的推理意图。

原始请求、响应、哈希、迁移回执和下载包保存在忽略目录 `.local/project-files-release-20261116/`，不提交凭据、真实连接标识或生成物。
