# 主动发现与有效提议

## 用户结果

本人尚未提出任务时，Rae 在已授权信息内识别与本人有关的变化和可提供的具体帮助，说明依据、价值与范围，征求本人的决定。接受后的工作进入原 TaskConsent 和 TaskExecutor，拒绝、完成及新增证据持续影响同一事项的后续判断。

提议前允许必要调研。当前问题与后台回顾复用已授权的腾讯文档读取、EWS 收件箱查询/正文读取、GitHub 官方只读工具，以及已有的微信资料和联网检索。服务端根据真实事件和有效租约确认调研来源，逐次复核连接范围。调研回执保留 agent 身份，不伪装本人指令。正式交付所需的附件或其他资料尚不可读时，事项记录 missingInputs，先调查或询问，不把尚不具备输入的工作标为 ready。

## 状态与来源

review_decisions 是一次判断的不可变记录，review_attention_items 是这些决定的当前投影，review_notification_outbox 保存实际投递状态。继续使用已有表与写入者。

观察决定支持静默、保存事项、通知、询问和提案。保存事项可记录尚待证据、已可帮助、已解决的状态，保存本轮为何采取该决定的简短理由。提案需要具体目标、预期成果和本人收益。同一事项内，目标和预期成果相同的提案保留原任务关联，改标题或换一批证据也不产生新卡片。原任务已被拒绝或撤销时，后续回顾需引用新资料、说明事实变化，并提出有实质变化的工作范围。

提案须提交 ready 事项和明确的空 missingInputs。必要输入未取得时以 watching 继续调研或 needs_input 询问。后续更新省略缺项字段时保留已有记录，清除缺项需引用新取得的资料。源绑定的新信息可安排一个明确 reviewAt，通过原 growth_wakes 到点触发一次回顾；该回顾不能自行续排。本人批准或拒绝提案后撤销对应的待触发回顾。

事项关联的每条证据仍绑定来源、代次和内容摘要。跨来源只使用当前场景已经授权的资料。既有跨场景关联依照原显式证据范围读取；历史资料和权限在迁移中保持原范围。

可帮助程度、通知相关性和执行许可分别判定。工作依赖允许有明确本人背景依据的推断，未被点名也可以提出有益建议。已知身份、本人最新要求优先于代理方法。资料中的要求保留外部来源身份。

## 调度与恢复

统一队列从旧微信队列迁入原事件与批次归属，从普通来源缓存迁入仍待分析的事件。已处理的历史批次、失败的旧运行与原预算保持原状态。迁移使用数据库事务和 marker，重启不重复导入。

来源有新信息时建立有界批次，同来源正在等待或执行的回顾先结清。排队按到期时间公平选择，来源撤回停止后续读取。失败批次及原资料保留，后续新事件独立成批。微信的指定会话手动分析优先处理新资料，无新资料时可在原预算内复核尚未终止的失败批次。无新信息、无本人安排时等待。

每条提案由原 TaskConsent writer 幂等创建，相关证据附入任务。同一事项已有提案时回查该任务的真实状态。批准时再次核对当前来源，撤回与取消沿用排空机制。旧消息、记忆版本、许可、任务 ID、用量及回执均保留并可导出。

## 验收

- 上午采集的当日评审邮件在本来源合并窗口后进入判断，文档增量不能占据邮件的处理机会；大量增量逐批覆盖，无空闲模型调用。
- 以合成的业务讨论、规则答复和角色证据验证原始事实进入真实模型请求，能够保存事项并提出具体帮助，尚未批准时没有交付或外部写入。
- 同名他人、无关群聊、已答复事项、已拒绝建议、缺失附件和未授权跨场景资料作为反例。方法假设不得覆盖本人要求。
- 一次观察后保持沉默的事项，可在后续会话或来源新增证据后接续；已批准提案保持同一任务和证据，结果可由后续回顾核对。
- 覆盖决定提交、提案创建、公开投递与回执之间的故障恢复，以及来源撤回、本人纠正和批准竞争。
- 核心修改运行完整 npm test、npm run check、npm run build。真实语义样本使用隔离数据、原模型连接与有限步骤，模型结果由人工逐项核对。

## 发布

固定完整源码快照，复用未变化的依赖。服务端 发布前暂停并排空，停止服务后备份完整数据与代码，在副本上演练迁移。切换后核对原资料、授权、消息、任务及回执，再恢复原启停意图。旧版本回滚使用匹配的数据备份，并保全升级后的新增数据。

## 语义验收方法

使用合成或经过人工脱敏的正反例，分别核对相关性、输入完整性、提案质量、来源及任务准入。机制回归使用离线模型；真实模型评估需要明确授权，并由人工判断语义结果，不把模型自述视为成功证明。实际资料、模型输入和个人用量回执在仓库之外保管。

## 提交前复核

2026-11-12复核本轮差异时，用确定性用例确认并修正了四处边界。一次性事项回顾失败后不再阻挡同来源的新资料；本人决定和事项更新会结清已到点但尚未运行的旧回顾，重启也会从真实任务状态补齐这一步；旧版提案经过事项更新后继续保留原任务关联和去重依据；不同UTC偏移的期限按真实时刻排序。相关回归覆盖pending/leased竞争、决定提交后的恢复、旧记录接续以及跨时区排序。
