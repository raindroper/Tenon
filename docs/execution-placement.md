# 执行位置默认规则

2026-11-16。项目操作默认使用项目所在客户端；远程观察、持久化、收信、提醒和不依赖本机环境的文本工作留在服务端。当前明确选择优先，同一任务等待和恢复时保持原设备与工作区。

## 变更

- 复用 TaskConsent、TaskExecutor、ProjectBroker 和原生会话，没有新增分类模型或调度系统。已有任务中的已批准位置只作为新委托的位置参考，不复制旧许可或重新执行旧任务。
- 将新请求中缺少目录与已保存的临时范围区分。缺少真实项目目标时询问；独立临时任务或改用服务器须有本次本人选择的依据。保存的旧范围及其哈希保持原格式。
- 设备的执行范围校验与就绪检查分开。离线、旧协议可保存明确目标；实际派发仍核对能力、授权、来源和范围。设备恢复或能力更新唤醒同一个操作，不搜索替代设备，不消耗等待轮询的模型调用。
- 客户端优先使用既有、已授权的 PATH，许可钩子和 Playwright 使用绝对路径的固定 Node。项目版本、依赖、已有修改和必要后端检查由原执行器完成，不增加额外审批流程。

## 验证

全量 1229 项离线测试通过，类型检查和生产构建通过。新增回归覆盖离线客户端与在线服务器并存、多个候选、缺少目录、明确临时任务、旧许可隔离及协议升级后同任务续做。等待时普通提醒仍可投递，无需新增任务或模型调用。

真实 Windows 原生引擎在隔离的本机项目中修复代码并执行 npm test：使用宿主 Node 22.19.0，Rae 固定 Node 24.22.1 仍负责许可钩子，已有未提交文件保持不变。原有真实浏览器、沙箱边界、等待后检查文件变化和原线程续做测试通过。模型响应是固定离线夹具，证明执行机制与工具链选择，不代表自然语言模型判断的成功率。

浏览器表单实测覆盖离线客户端默认、目录必填、离线委托提交、已确认位置沿用及服务器不成为隐式默认。

该版本已部署至现有生产实例，服务端、Linux worker 和网页使用同一快照；Windows 更新为 0.1.30。安装包延续原更新签名，基于已发布 0.1.29 保留其微信组件，逐文件摘要验证一致，并用新包内实际代码通过四项原生集成回归。

Linux 候选环境 42 项流程回归通过。重复初始化生产副本后，授权、项目操作、回执、等待依赖和已交付文件均与备份一致，原项目范围哈希也逐项一致。切换前备份已校验，切换后原记录比对通过；登录、匿名访问限制、状态心跳、worker 在线及历史成果下载均已检查。维护前启用的推理设置已按版本核对恢复，没有为验证新增付费模型调用。

## 数据与边界

没有新增可写项目注册表或数据库版本迁移。部署前在生产数据库副本上检查重复初始化与旧项目范围哈希，部署时保留原数据备份及旧镜像回滚入口。历史任务、许可、用量、等待条件和已交付文件不因新的默认位置重新解释。

当前支持已登记的 Windows 客户端和显式选择的 Linux 独立工作区。WSL、任意远程开发环境、GPU 调度和跨设备迁移没有新增实现。开发机缺少工具、后端网络或必要配置时仍需要补齐真实条件；系统会说明未完成的验证，不以演示代码替代。

## 代码审查复核

2026-11-16 针对本次选址改动单独审查入口一致性、授权边界、状态更新和复杂度，复现并修正三项问题：

| 触发条件 | 审查发现 | 修正 |
| --- | --- | --- |
| 填写任务表单时后台新增其他项目记录 | 表单会重新计算默认位置，可能改选另一台电脑 | 打开表单时保存设备与目录；后台只更新设备状态，用户主动切换场景或设备时才重新选址 |
| 对话批准原项目提案，客户端离线或协议旧 | 批准入口仍要求在线，与新任务及表单入口不一致 | 新委托和对话批准共用范围准备；已明确的目标可保存等待，不创建替代任务 |
| 用户已经在当前消息的设备选择器选择服务器 | 仍可能索要目录或文字选址依据 | 当前选择直接作为设备依据，服务器资源确认仍留在原任务卡 |

同时删除了重复的批准入口就绪判断、界面契约中不会返回的撤销字段和测试中的 `any`，范围校验条件改为明确的布尔类型。没有新增依赖、数据表、分类模型、执行器或配置开关。源码中的请求/持久化范围区分保留，因为历史范围哈希必须稳定。

新增两项自动回归先复现失败，修正后全量 1231 项测试通过，类型检查和生产构建通过。实际浏览器验证后台记录更新、原设备被移除及最终提交的设备/目录；移除设备只阻止提交，不自动改选。该审查证明已覆盖的实现与回归边界，不将测试通过等同于所有未来场景都没有缺陷。

复核后的修复已发布到应用服务和网页。Linux 候选 44 项回归通过，生产副本原范围哈希与重复初始化检查通过；切换前备份和切换后原记录比对、登录、匿名访问限制、状态心跳与执行端在线检查通过。Linux worker 的编译产物摘要未变，保持原镜像和运行进程；客户端保持原 0.1.30 签名包。维护前设置已恢复，本次没有新增依赖或数据迁移。
