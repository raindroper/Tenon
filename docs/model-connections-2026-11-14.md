# 多模型连接与配置需求及实现方案

更新日期：2026-11-14（Asia/Shanghai）。状态：0.1.25 已完成开发、验证及部署。

AR 将支持保存多个自定义 API 连接和多个 ChatGPT OAuth 账号，通过全局默认、后台默认和场景覆盖选择“连接、模型、思考强度”。已有连接、对话、记忆和任务记录继续保留。连接失效时保留选择与进展，由本人修复或手动更换，不自动换账号、模型或计费来源。

需求最初以文档整理确认，随后本人明确授权开发并部署。当前实现与验证见第 18 节；未进行真实 ChatGPT 账号登录或模型推理探针。当前产品和执行边界继续以 [README](../README.md#当前产品契约)、[内核契约](kernel-upgrade-2026-11-07.md)和[项目执行契约](local-project-harness.md)为准。

## 1 已确认需求

| 编号 | 需求 | 可观察结果 |
| --- | --- | --- |
| R01 | 保留 Base URL 加 API Key 的接入方式，允许保存多个连接 | 添加新连接不覆盖旧连接，切回时无需重新填写 |
| R02 | 新增 Sign in with ChatGPT，简称 SIWC | 用户通过 OAuth 授权使用 ChatGPT 套餐调用模型 |
| R03 | 保存多个独立 ChatGPT 账号注册，手动选择使用哪个 | 不同场景可以引用不同账号，账户之间不串凭据 |
| R04 | 设置全局默认连接、模型和思考强度 | 未覆盖的场景跟随全局默认 |
| R05 | 设置独立的后台默认连接、模型和思考强度 | 后台可单独配置，未单独配置时继承全局默认 |
| R06 | 在对话中选择模型连接和思考强度，并持久保存到当前场景 | 刷新页面、重启和再次进入场景后仍保留选择 |
| R07 | 场景明确区分跟随全局与使用场景配置 | 修改全局只影响跟随者；场景可恢复跟随 |
| R08 | 连接和模型能力决定可选模型、思考档位及其他参数 | 不假定不同供应商具有同一组参数或相同档位含义 |
| R09 | 失效连接保留配置，支持修复、更换场景配置或恢复跟随全局 | 不自动清空配置，不静默回退 |
| R10 | 配置变更用于后续新回合、新任务；已开始运行固定选择 | 同一回合的工具往返及恢复不因全局变化而换账号 |
| R11 | 保存配置、完成登录或读取模型目录不自动开启真实推理 | 登录状态、模型授权和推理启停分别显示和管理 |
| R12 | 延续单一运行时、授权、用量和生命周期契约 | 模型选择不产生执行许可，不重启历史任务，不新建第二套代理调度 |

讨论中的 `apikey-1`、`apikey-2`、`siwc-1`、`siwc-2`，以及生活、开发、AI 调研与具体模型名称，只用于说明配置关系。它们不是需要预置的真实账号、固定场景分类或实际模型分配。模型和思考档位必须以对应连接的能力为准。

本期不包括自动内容分类选模、账号轮换、质量升级、自动跨连接容灾、多模型互审、独立路由服务器或按金额计算的预算系统。早期自动分派设想保留在 Git 历史供回查，不作为当前待办。

## 2 配置对象及所有权

| 对象 | 保存什么 | 谁可以引用 |
| --- | --- | --- |
| 模型连接 | 稳定 ID、显示名称、协议、服务地址、认证方式、凭据引用、账号身份及状态 | 全局默认、后台默认、多个场景和运行 |
| 模型能力目录 | 某连接可选模型、参数能力、来源与更新时间 | 设置和选择校验；属于可重建缓存 |
| 完整模型选择 | 连接 ID、真实模型 ID、思考配置及适用的可选生成参数 | 默认配置或场景覆盖 |
| 全局默认 | 一份完整模型选择，或新实例的未配置状态 | 没有覆盖的普通场景，以及选择继承的后台默认 |
| 后台默认 | 跟随全局，或一份完整模型选择 | 符合后台用途定义的新运行 |
| 场景设置 | 跟随全局，或一份完整模型选择 | 当前场景的新交流及适用的新任务 |
| 运行绑定快照 | 已解析选择、来源、用途、连接身份与配置版本 | 当前回合或任务及其恢复 |
| 服务连接 | Hub 搜索、媒体等自己的入口与凭据引用 | 对应服务，不跟随模型选择切换 |

一个连接可以被多个场景共用；一个场景可以改为引用另一个连接。场景中不复制 API key 或 OAuth token。

多账号不是进程级的唯一 `activeAccount`。每次调用以所属运行的连接引用确定身份；两个场景可以同时使用 `siwc-1` 和 `siwc-2`。登录界面中当前正在查看哪个账号，不得改变其他场景或运行的请求身份。

场景模型设置是使用偏好，不拥有新的任务许可或资料授权。外部文档、工具结果和模型输出不能修改绑定、添加连接或把旧授权扩大到新目的端。

## 3 继承与覆盖规则

### 3.1 场景与后台默认

场景只保存两种状态：

- 跟随全局：保存继承标记，不复制当前全局值。
- 使用场景配置：保存完整的“连接加模型加思考配置”。

后台默认同样保存“跟随全局”或完整配置。全局、后台与场景不逐字段拼接，避免从一个账号继承模型、从另一个账号继承凭据。

| 变更 | 跟随全局的场景 | 使用覆盖的场景 | 跟随全局的后台默认 | 独立后台默认 |
| --- | --- | --- | --- | --- |
| 修改全局默认 | 下一个新回合使用新值 | 不变 | 下一次后台运行使用新值 | 不变 |
| 修改后台默认 | 不变 | 不变 | 按新设置解析 | 按新设置解析 |
| 修改某个场景 | 只影响该场景 | 只影响该场景 | 不变 | 不变 |
| 场景恢复跟随全局 | 使用当时及以后全局值 | 清除该场景覆盖 | 不变 | 不变 |
| 后台恢复跟随全局 | 不变 | 不变 | 使用当时及以后全局值 | 清除后台覆盖 |

显式选择的值即使恰好等于全局默认，也仍然属于覆盖；之后全局修改不能改变它。全局尚未配置时，继承者显示未配置，不从连接列表挑选第一个代替；已配置但失效时显示第 5 节对应的故障，不伪装成缺少设置。

### 3.2 示例

以下仅验证语义，不承诺示例模型对实际账号可用。

初始全局为 `siwc-1 + gpt-6-astra + ultra`：

- 场景 A 选择跟随全局。
- 场景 B 明确保存 `apikey-1 + deepseek4.1flash + 极致`。
- 场景 C 明确保存与初始全局相同的值。
- 后台默认选择跟随全局。

全局改为 `siwc-2 + gpt-6.1-sol + 该连接支持的档位` 后，A 和新的后台运行跟随；B、C 保持原选择。B 只有在本人点击恢复跟随全局后才改为继承。

### 3.3 后台工作的归属

独立后台默认是已确认需求。“工作在后台进行”不等于“使用后台默认”：本人已经委托的任务不能因为页面关闭、异步等待或转入后台就换模型。

| 工作类型 | 本方案处理 | 确认状态 |
| --- | --- | --- |
| 普通本人交流 | 场景覆盖，否则全局默认 | 已确认 |
| 无场景归属的自主学习与被动回顾 | 后台默认，否则全局默认 | 已确认的后台默认适用范围 |
| 已获准任务及项目执行 | 建议登记任务时继承来源回合的完整选择，随后固定 | 任务固定已确认；登记时机为实施建议 |
| 有场景归属的自主资料回顾 | 使用后台默认，场景仍决定可读资料范围 | 0.1.25 已采用 |
| 本人交流或任务附带的 observer、reflector 等辅助记忆处理 | 跟随所属回合或任务，避免同一处理链隐式跨账号 | 0.1.25 已采用 |
| 定时回访 | 先区分本人已委托工作与自主回顾，再走对应规则 | 用途映射需在实现前核对 |
| 已有日常提醒的到点投递 | 不调用模型，不需要模型连接 | 延续产品契约 |

实现使用受信任的运行用途和来源分类。`mode=growth` 也用于本人交流，不能据此直接选择后台模型；不新增模型分类器，也不靠自然语言关键词猜用途。0.1.25 的两类记忆／回顾路由按上表固定。

## 4 配置生效与运行快照

实施建议采用以下时点，消除设置修改与排队之间的竞争：

1. 本人消息被服务端接受时，原子解析场景设置与全局默认，并将快照绑定该消息的持久事件；排队期间不随设置漂移。
2. 获准任务登记时，继承来源回合的选择并保存任务绑定；由其他明确入口创建的任务，在登记时按该入口的上下文解析一次。
3. 自主后台事件可先合并。真正创建有界后台运行时解析后台默认；恢复同一运行时使用原快照。
4. 后续每次请求重新检查连接状态、身份版本、任务许可、当前资源授权和取消状态，但不重新选择模型。
5. 任务换到另一个场景显示或从那里收到补充要求，不自动改变原任务绑定。

消息受理时，绑定与原始消息在同一持久提交中保存；配置读取和受理提交使用同库事务或提交前版本重核。事件收件箱位于另一存储时，以已受理消息中的不可变绑定重建事件，事件只携带引用或不可变副本，不重新读取当时的默认配置，也不成为独立修改绑定的入口。不能假定消息库和事件库存在跨库原子提交。

快照包含连接 ID、协议及目的端版本、账号身份版本、模型 ID、请求思考配置、参数适配版本、配置来源和记录时间。不包含任何凭据。

需要区分两种变化：

| 变化 | 对既有运行的影响 |
| --- | --- |
| 修改全局／后台／场景选择 | 不改变已接受回合及已登记任务 |
| 连接改显示名称 | 不改变身份与绑定 |
| 同一 OAuth 注册正常刷新 token | 使用该连接最新有效凭据，不视为换模型 |
| 修复 API key | 新调用可用新凭据；不能仅凭连接 ID 断言密钥所属账号相同，旧运行恢复前核对修复声明与目标 |
| 更改 Base URL、协议、账号／工作区或可发送资料范围 | 属于实质变更；旧快照不可自动向新目标发请求 |
| 停用、登出或确认撤销连接 | 阻止该连接新请求；正在处理的请求进入取消／排空，不取消无关连接 |
| 恢复连接 | 不自动复活终态任务或重放未知外部操作 |

已发送的数据不能通过后续撤销收回。退出或撤销的完成状态必须反映真实排空与远端撤销结果。

运行中显式换模型的界面与通用恢复能力不是已确认的首期功能。最低要求是保留进展、允许停止，并在经验证的恢复入口重新选择后留下变更记录；不得以从头重跑任务代替续作。原生 Codex 会话跨模型恢复若未验证，需明确限制为新任务使用新选择。

## 5 连接失效与恢复

连接选择、认证状态、模型可用性和运行故障分别保存。一次失败不能直接清空整个连接，也不能把所有场景置为不可用。

| 情况 | 保留内容 | 行为与用户操作 |
| --- | --- | --- |
| 临时网络中断、超时或临时服务错误 | 凭据、绑定、已收正文和进展 | 报告暂时不可用；仅在同一连接及原预算内进行安全的有限重试 |
| API key 缺失或确认失效 | 连接 ID、场景覆盖和历史 | 停止依赖它的新请求，提供修复连接 |
| OAuth access token 正常到期 | 原注册身份和配置 | 在连接内部刷新，不能自动切另一个账号 |
| refresh token 确认失效、授权撤销或身份不匹配 | 连接记录与引用 | 要求重新登录；身份不匹配时不覆盖原注册 |
| 登录成功但未获套餐调用权限 | 登录身份与注册 | 显示尚未授权模型调用，提供明确授权入口 |
| 套餐或应用用量达到限制 | 登录与配置 | 暂停受影响请求，提供管理用量入口；不推断重置时间或切计费方式 |
| 模型下架、账号无权使用模型或参数不支持 | 原选择和诊断 | 标明具体模型／参数不可用，请本人修改 |
| 全局默认引用的连接失效 | 全局配置及所有场景引用 | 影响实际引用同一失效连接的继承与显式覆盖；其他有效连接继续可用。若只有某个模型不可用，则按该模型缩小影响范围 |
| 场景覆盖失效 | 场景覆盖 | 修复连接、选择另一完整配置，或明确恢复跟随全局 |
| 流中失败、未完成或缺失终止事件 | 收到的公开正文和实际用量 | 标记未完成，不能把已有文字当作成功结果 |

三个主要恢复操作：

- **修复连接**：更新密钥或重新登录同一注册。所有引用该连接的配置继续保留；需要恢复的运行仍走既有有效性检查。
- **更换当前选择**：只改变选中的全局、后台或场景配置，不改其他引用者。
- **恢复跟随全局**：显式清除后台或场景覆盖，不因故障自动执行。

不把每个 HTTP 401／403 都解释成失效密钥；保留经脱敏的状态、结构化错误码、请求 ID 和阶段，区分权限、资格、地区、额度与凭据问题。已产生公开输出、工具受理或未知副作用时，不自动重放整个回合。基础设施恢复不制造新的任务许可。

**停用与删除属于实施建议：** 设置页先显示默认项、场景及活动任务引用。存在当前引用时优先停用或归档；硬删除前必须解决引用，不能暗改为继承。历史调用保留连接 ID 和当时显示信息，即使连接已归档仍可回查。

## 6 设置与对话交互

### 6.1 模型连接设置

同一页面集中提供：

- 连接列表：名称、类型、可识别账号／工作区标签、登录与授权状态、最近错误，以及使用该连接的默认项和场景。
- 自定义 API 连接：名称、Base URL、密钥写入／清除入口、已支持的协议类型、模型目录或手动模型 ID。
- SIWC 连接：添加账号、重新登录、退出、管理用量、刷新模型目录。添加账号不修改任何默认项。
- 全局默认：连接、模型和思考配置。
- 后台默认：跟随全局开关，或独立的完整选择。
- 连接检查：区分配置校验、读取模型目录和真实推理测试；真实推理测试需要明确点击，不能随登录或保存自动发生。

账号标签用于区分注册，不以邮箱作为唯一身份。SIWC 可以保留多个注册，切换一个注册无需退出其他注册。[官方账户管理](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)

连接选择应显示当前有效结果和配置来源。“已保存”“已登录”“已授权模型调用”“模型目录已获取”“最近推理成功”是不同状态，不能合并成一个无条件的可用标记。

### 6.2 对话中的模型选择

对话输入区展示当前场景有效配置，例如：

- `跟随全局 · 连接名称 / 模型名称 / 思考档位`
- `场景配置 · 连接名称 / 模型名称 / 思考档位`
- `场景配置不可用 · 连接需要重新登录`

打开选择器后按连接、模型、思考强度依次选择，保存完整配置并明确提示“用于当前场景的新回合”。提供恢复跟随全局。主对话也必须关联其现有稳定场景身份，不以浏览器本地草稿作为真源。

当前逐消息的思考强度选择应迁为场景持久设置；旧消息上的思考记录继续回查。首期不再保留一个隐藏的逐消息覆盖层与场景设置竞争，历史已经接受的消息仍按原记录处理。

选择变化不清空对话或记忆。向新模型继续发送历史时，重建其支持的文本、图片和工具上下文，不能把旧供应商专用 reasoning 对象或不兼容的工具消息原样传输。

### 6.3 保存与冲突

模型设置写入独立于推理启停和任务取消。保存过程中显示提交状态，失败保留草稿并明确反馈，不能先显示已生效。

使用现有 RuntimeApi 命令语义、请求幂等和配置版本检查；两个页面同时保存时不能用旧整页设置覆盖另一页面新加的连接。OAuth 刷新不触发设置页重新保存、运行时重启或全局取消。

## 7 模型目录与思考强度

模型和参数能力按“连接、协议、模型 ID”确定，不仅按模型名确定。目录属于供应商声明，不是工具往返、图片或上下文能力已经通过验收的证明。

- SIWC 使用所选注册的 token 获取账号模型目录，显示服务端提供的名称，提交真实 slug；模型目录按账号隔离缓存，账号切换后更新。[官方模型目录](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)
- 自定义 API 可以读取其支持的目录接口；没有目录时保留手动填写。不能假定所有兼容接口都提供标准目录。
- “跟随全局”属于 AR 配置继承；“服务商默认”属于参数省略，必须在界面上分开。
- `ultra`、`max`、“极致”等不作为跨供应商通用等价档位。保存适配器识别的语义／真实值和能力版本，避免统一映射导致请求参数失真。
- 当前 AR 的 `auto` 是现有推理选择策略，不应改名后当成服务商默认。旧连接迁移时保留其行为；新连接只展示适配器确实支持的选项。
- 切换连接或模型后重新校验思考配置。原档位不适用时，要求用户明确选用支持项后保存；不暗中降档。
- 原有输出上限为可选设置。SIWC 不接受的上限不能假装已生效；自定义 API 仍保留适用的原值。新连接默认不主动压低供应商输出上限。

模型列表读取不发送场景正文。若某模型只能聊天而不能满足项目工具协议，设置可展示其能力边界；具体执行必须拒绝不兼容调用，不能在失败后偷偷换模型。

## 8 数据结构与持久化建议

以下是逻辑结构，不要求新建服务或重复数据库。

| 结构 | 关键字段 | 约束 |
| --- | --- | --- |
| ModelConnection | id、name、kind、protocol、endpoint、credentialRef、identityRef、editRevision、bindingRevision、identityRevision、status | ID 稳定；编辑冲突版本与影响调用的版本分开；一条 SIWC 连接对应一个独立注册 |
| OAuthRegistration | issuer、subject、issuedClientId、可验证的工作区关联、grantedScopes、expiry、secretRef | 以已验证身份加注册区分；邮箱和显示名称不作为授权身份 |
| HostIdentity | 稳定 host ID、所属运行环境 | 与账号分开，重启／换账号不重新生成 |
| ModelSelection | connectionId、modelId、reasoning、generationOptions、adapterVersion | 完整原子保存；不可逐字段跨连接继承 |
| ModelDefaults | global、background、revision | background 是 inheritGlobal 或 explicit；global 可为未配置 |
| SceneModelPreference | caseId、mode、selection、revision | mode 是 inheritGlobal 或 explicit |
| ResolvedModelBinding | selection、source、purpose、bindingRevision、identityRevision、resolvedAt | 作为消息事件／运行／任务的固化记录，不形成新任务状态机 |
| ConnectionDiagnostics | 检查阶段、错误类别、模型标识、脱敏码、requestId、时间 | 可重建状态不替代连接或调用事实 |
| ModelCall 调用事实 | connectionId、身份版本、模型、思考配置、runId／taskId、调用 ID、状态和供应商实际用量 | 在现有存储中补齐普通请求的持久记录，由同一 UsageTracker 写入，不另建计费服务 |

editRevision 用于编辑冲突检查；显示名称变化只更新这一版本。bindingRevision 用于实际目的端、协议和可发送资料范围的变化，identityRevision 用于注册身份变化。正常 token 轮换只更新凭据版本，不使旧绑定因普通刷新失效。运行检查 bindingRevision 与 identityRevision，不因连接改名误停。接收配置写入和开始调用之间需要可验证的版本核对，避免校验一个目标、实际向另一个目标发送。

复用 [SecretStore](../server/secrets.ts) 的平台保护与按文件命名机制扩展连接凭据。Windows 保留 DPAPI，Linux 保留现有加密及所有者密钥。OAuth 整组 token、expiry、scope 必须一起原子替换，不把 refresh token 存入普通设置、场景记录或 run 快照。

公开状态、前端、日志、普通导出和诊断不得返回 access token、refresh token、ID token、API key 或包含凭据的授权 URL。完整私有备份继续按现有备份边界保存，并保留恢复所需的密钥材料。

模型配置仍通过唯一 [RuntimeApi](../server/runtime.ts) 写入；HTTP、桌面桥和 UI 不直接操作内部数据库或凭据文件。模型目录和界面有效配置都是投影，不能成为第二份可写真源。

## 9 SIWC 登录与凭据生命周期

### 9.1 接入路径

采用 AR 自有 SIWC 注册和公共 Responses API。旧 Codex CLI 登录缓存不作为 AR 的运行时 token 共享接口，也不让普通 Mastra 对话改由 Codex agent loop 执行。官方对已有本地／开源 app-server 认证保留兼容说明，并建议迁移 SIWC；这不保证任意旧 token 可用于新的公共接口。[App-server 认证说明](https://learn.chatgpt.com/docs/app-server#auth-endpoints)

优先评估官方 Sign in with ChatGPT DevKit 和维护中的 OAuth／OpenAI SDK，核验版本、许可、平台存储与多注册行为后再采用。只补 AR 必要的存储、连接和传输适配，不另建认证服务或代理框架。[官方 DevKit 接入示例](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)

### 9.2 本机登录

1. 本人点击添加 ChatGPT 账号，创建独立的待完成登录记录，不影响现有绑定。
2. 准备本机稳定 host ID、回调监听、随机 state／nonce 和 PKCE。
3. 首次使用动态注册入口，后续登录复用已颁发 client ID。回调严格校验 state、登录尝试归属和预期注册。
4. 校验 ID token 的签名、issuer、audience、nonce、有效期和返回身份；检查实际授予的套餐调用权限。
5. 原子保存注册与受保护凭据，只向界面返回连接状态及显示信息。
6. 读取可用模型供选择；本人保存默认或场景配置后才影响未来调用。

实际参数遵循[注册与登录文档](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)：HTTP loopback 使用 `127.0.0.1`，每次授权和换码使用完全一致的回调 URI；resource 指向公共 API，身份 scope 与套餐调用 scope 分开核验。登录取消、回调重放、过期 code 和返回不同账号必须有独立处理。

### 9.3 刷新与登出

每个可续期会话单独串行刷新；并发请求共享一次刷新结果，不用全局锁阻塞其他账号。按 token 响应的期限进行按需刷新，不通过模型请求轮询连接健康。

刷新成功后原子替换整组凭据；旧刷新结果不得覆盖新登录或登出后的状态。刷新保存失败、请求取消和进程重启均需确定性故障注入，不能把更新中的凭据标为已完成。

退出时关闭该连接的新请求入口，处理在途请求与刷新，尝试撤销可续期会话，再清除本地 token；保留注册映射以便重连。有限撤销重试仍失败时，可以完成本地退出并清除 token，同时显示“远端撤销未确认”，提供 ChatGPT 设置中的断开入口。不能把本地删除说成远端已撤销。普通调用或刷新遇到临时网络错误时保留凭据；确认失效才进入重新登录流程，这条保留规则不取消本人主动退出的决定。[官方会话管理](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)与[错误恢复](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)

### 9.4 自托管服务器

远程 AR 后端无法直接接收用户浏览器所在机器的 loopback 回调。不能把本地登录按钮接到远端监听后就宣称远程登录完成。

建议优先复用 AR 桌面主进程辅助本机 OAuth，并经现有已认证的设备／后端通道导入目标连接。导入请求固定目标 AR 实例、连接和登录尝试，校验身份后写入服务器 SecretStore；token 不进入 renderer 或任意回调地址。纯浏览器远程登录是否作为首期必需入口，见待决策项。

服务器保留自己的 host ID。会话转移后由服务器拥有刷新权，桌面端不继续刷新同一会话，不双向同步凭据文件。转移确认丢失时按持久操作 ID 核对结果，不能让两端都恢复刷新。官方目前不保证这种转移会话具备每个 host 独立的用量归属或撤销能力。[自托管 VM 指引](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)

当前文档为本地个人项目及开源应用提供路径；付费或对外远程托管应用有单独申请要求。AR 的项目许可证尚未确定，现有生产 VM 的适用资格、实际账号权限及部署方式必须在真实接入前核对，不因源码公开而推定已满足。[SIWC 适用范围](https://developers.openai.com/siwc/token-sharing-open-source)

## 10 模型适配与单一调用链

保持一套生产 Mastra 运行时及一个 RuntimeApi：

```text
全局默认 / 后台默认 / 场景覆盖
                 ↓
       用途解析与完整绑定快照
                 ↓
     连接身份和授权核对 / 凭据解析
           ↙                 ↘
Mastra LanguageModelV4    已有项目 Responses 中继
           ↘                 ↙
      共用连接与协议规则 / 实际用量记录
                 ↓
     自定义 API 或 SIWC Responses

Hub 搜索和媒体 → 独立服务连接与凭据
```

协议适配不新增任务许可或工具执行器。两个传输入口复用同一连接解析、SIWC 字段规则、认证生命周期和错误分类，不能各自读一份 token。

### 10.1 自定义 API

保留当前已验证的 DeepSeek 兼容路径。连接的认证类型和通信协议分别建模；“API key”本身不表示它一定支持 Chat Completions、Responses 或所有工具。

使用已安装框架及维护中的 provider SDK，在一个 provider 工厂中按已支持协议创建模型。新建自定义入口必须明确协议，不能只根据模型名猜。当前连接的行为、可选输出上限和思考策略通过迁移保存。

### 10.2 SIWC Responses

适配器应满足当前[预览约束](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)：

- HTTP 使用 `store:false`、`stream:true` 和完整 input 数组；system 内容转换为 instructions 或 developer 消息，保持原指令优先级。
- HTTP 不使用 `previous_response_id` 延续历史。AR 负责上下文重建和持久记录。
- 省略不支持的 `max_output_tokens`、`temperature`、`top_p`、`metadata` 等字段；完整受支持范围以固定版本适配规则与契约测试为准。
- function／custom 工具按支持的 namespace 或 additional_tools 表达，保持调用 ID、工具名和结果关联。
- 不把不支持的 hosted MCP、原生 computer use、tool_search、图像生成等服务端能力包装成可用。AR 本地工具仍沿用现有授权执行路径。
- 输入能力按模型核对；文件、图片、上下文大小及多模态支持不能仅从模型名称推断。

对框架自动附带的无效字段由适配器规范化；对本人明确选择但不支持的参数，应在保存或调用前报错，不能静默丢弃并声称生效。

正常完成必须有供应商终止事件；处理流中失败、未完成、断流与取消并保留已有公开文本。仅列出模型或收到文字不等于推理成功。[Responses 完成要求](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

若调用者需要 `doGenerate`，SIWC 仍以 HTTP SSE 完成后聚合结果，不能改走不支持的非流式路由。普通 actor、记忆 observer／reflector、连接测试和原生项目请求都需覆盖，避免只有聊天入口支持。

### 10.3 已有 Codex 项目执行

继续使用固定上游执行器、独立 CODEX_HOME、严格配置和 task-local token。OpenAI OAuth 凭据保留在 AR 后端；不加载本人全局 Codex 配置、登录缓存、插件或权限。

项目模型中继核对任务绑定与连接当前状态，替换与全局 settings.model 直接比较的逻辑，并清理 SIWC 不支持参数。原生工具、审批、取消、排空和回执仍由现有执行契约负责。

### 10.4 Hub 服务解耦

当前 Hub 搜索和媒体读取全局模型地址与 key，必须在接入 SIWC 前拆开为明确的服务连接引用：

- 迁移时保留现有 Hub 地址和凭据用途，不能把切换后的 ChatGPT token 发给 Hub。
- 模型选择变化不修改搜索／媒体配置；共享的旧 key 可以迁为明确的服务凭据引用，生命周期不得被模型连接删除意外破坏。
- 只通过 Hub 支持的 HTTP／配置接口集成，不修改 Hub 上游，不读取其账号备份作为 token API。
- 保留当前视频提交串行至私有文件保存的限制；不影响其他对话响应。

## 12 用量与运行诊断

继续仅记录供应商实际报告的 token；缺失、部分报告和未使用模型分别保留原语义。不引入价格目录、金额预算、字符估算或把套餐百分比换算成 token。

当前普通 UsageTracker 持久保存 run 聚合和 pending 数量，逐调用 ID 仍在内存中；项目路径另有持久模型回执。因此实施需要在现有存储内补齐普通 ModelCall 请求事实，不能把现状描述为已经具备完整逐请求账本。

请求事实增加连接 ID、身份版本、实际请求模型、请求思考配置、选择来源、运行用途、供应商 request ID，以及可用的响应模型标识。普通请求与项目请求由同一 UsageTracker 统一登记、幂等结算；run 合计作为可重建投影，项目操作回执引用对应调用事实并保留自己的协议状态，不各自累计一份竞争用量。响应自报模型不等于已验证底层部署身份。

每次真实 provider 请求在发出前持久保存 pending；请求结算、pending 清除及聚合投影提交保持可恢复且幂等。网络失败、取消、重复 finish 和重启不得丢失或重复计量。现有只有聚合数据的历史记录继续按原粒度读取，不反推或伪造逐请求记录。登录、token 刷新、模型列表请求不计为模型 token 消耗，也不伪造零 token 的完整推理回执。

运行历史可以展开查看“本次为何使用此连接和模型”，不显示私有推理内容或凭据。主界面只显示必要状态。历史缺少连接归属时标为未知，不根据当前默认倒填。

## 13 迁移与回滚

### 13.1 旧单连接迁移

1. 在受控生命周期中停止接受受影响的新操作并排空，备份数据和对应代码版本。
2. 为现有 Base URL、key 来源、模型及思考策略创建一个稳定的旧连接；保留原协议和生成参数。
3. 全局默认引用该连接；后台默认设为跟随全局；已有场景默认设为跟随全局。这样初始行为不变，后续继承语义明确。
4. 保留所有已有连接器、Hub 服务和凭据来源，完成 Hub 独立服务绑定；不重新授权或扩大资源范围。
5. 环境变量中的旧 key 只绑定这条迁移连接，并在设置中说明其来源；不得成为所有新连接的通用后备 key。
6. 保留旧消息上的逐消息思考事实、任务许可、历史模型快照、实际用量与启停意图。登录和迁移不自动启用推理。
7. 记录 schema／迁移进度并验证幂等。数据库与文件凭据的跨存储更新采用可恢复迁移日志，不声称跨文件天然原子。
8. 切换内部调用到唯一新入口，删除旧写入路径；错误不能静默回退到默认地址。

旧进行中任务若已有足够模型信息，可绑定到已核对的旧连接；无法证明原身份或参数时保留待核对状态，不能用当前全局值伪造历史快照。终态任务、历史提案和旧授权不因迁移重新激活。

### 13.2 回滚边界

版本不兼容时使用对应代码与成套数据备份，不能只把旧代码指向新 schema。回滚前保全升级后的新消息、回执、产物和配置；无法无损回退时保持暂停与可读导出。

OAuth refresh token 会在远端轮换。恢复旧本地备份不等于恢复旧 token 的有效性；不得启用一个可能已轮换或撤销的旧会话。必要时保留连接注册并要求重新登录。不能以回滚为由恢复已经撤销的任务或资源权限。

发布属于后续实施阶段。本轮不改变部署、服务、账号授权或真实推理状态。

### 15.2 失效与身份边界

- API key 修复后引用者保留选择；后台和场景无需重新填写。
- OAuth 到期仅刷新同一注册；重复登录不同身份不能覆盖原连接。
- 同会话并发刷新、刷新结果晚于登出、凭据落盘失败和重启通过确定性故障注入验证。
- 暂时网络失败、配额不足、缺少套餐权限、模型不可用和撤销分别显示；均不跨账号回退。
- 停用或登出只影响该连接；取消／排空和远端撤销未确认保持可见。
- 连接端点、工作区或身份改变时，旧运行不能自动向新目标发送。
- token 不进入 UI、日志、普通导出、Hub 请求或原生执行器子进程。
- 转移到服务器后只有一个刷新所有者；丢失确认不造成双端并发刷新。
- 删除或归档连接保留历史归属，不自动改写场景覆盖。

### 15.3 协议与运行

- 主 Mastra 交流、图片输入、函数工具往返、辅助记忆以及项目 Responses 中继分别覆盖。
- 用捕获的离线出站请求验证 SIWC 字段、完整历史、system 转换、namespace、工具 ID 与结果回传。
- 显式不支持的思考档位或输出上限不能静默生效；provider 默认与继承状态分别验证。
- API key 链路保持原协议、思考与输出行为；不向它误发 SIWC 专属设置。
- 中途修改全局／场景后，同一回合多步、排队消息和任务恢复仍用已接受快照。
- 消息已持久受理但事件未提交时故障退出，随后修改默认再恢复；重建事件和后续请求仍使用原消息绑定，原消息不重复受理。
- `mode=growth` 的本人交流不能误走后台默认；后台用途待定项确定后逐类写回归。
- 部分正文已交付后失败、重复 finish、取消、延迟回执和崩溃恢复不重放副作用、不重复计量。
- 旧配置迁移、环境变量绑定、Hub 独立连接、启停状态和旧数据导出均保留。
- 本人对话和新获准任务不新增总时长截止；历史有限 deadline、步数、被动回顾预算和单请求超时继续生效。
- 已有提醒投递继续零模型调用；没有新事件时不增加模型健康轮询。

核心运行时、存储及权限接入完成后必须运行 `npm test`、`npm run check`、`npm run build`。测试使用离线网络守卫与隔离临时目录；沿用现有 reasoning、settings-concurrency、secrets、memory、metering、project 和 lifecycle 回归，并更新已被新语义替代的断言。

真实验收单独覆盖登录、模型授权、目录、文本、工具、图片及实际部署路径，记录供应商用量和已验证范围。只有模型目录成功不能代替真实推理终态和工具往返验收。

## 18 实现与验证记录

0.1.25 实现了多 API 连接、多个独立 SIWC 注册、全局与后台默认、场景持久覆盖、完整运行绑定、受控修复重试，以及按连接隔离的最近故障诊断。内核数据版本升级到 7。旧模型设置迁入独立连接，后台和旧场景初始跟随全局；Hub 保留独立凭据。原逐消息思考选择 UI 已替换，旧消息字段继续按旧协议读取，旧 HTTP 模型设置写入口关闭。

通用基础由现有 SDK 承担：代理运行继续使用 Mastra／AI SDK，推理使用 OpenAI 和 DeepSeek provider；OAuth/OIDC 的发现、PKCE、授权码与刷新处理、签名验证和撤销使用 oauth4webapi。AR 适配层只处理 SIWC 特有参数、账户存储和生命周期、能力差异及运行绑定。jose 仅用于开发测试的签名夹具。

本期采用的配置规则：自主回顾使用后台默认，对话附带的记忆处理跟随当轮，获准任务固定来源回合的选择。远程首次 SIWC 登录使用新版桌面客户端接收本机回调，授权码经原 AR 登录会话提交，token 交换及保存均在后端。远程普通网页可以使用已保存连接，尚不提供没有本机辅助的首次 OAuth 登录。已有任务不支持任意模型热切换。

修复 API key 后，只有明确重试、相同服务地址与协议且原回合未受理工具操作时，才刷新原选择的身份版本；原消息绑定不被覆盖，事件保存重试变更记录。显式未配置的快照不会在后续后台派发时自动取得新默认。停用连接等待关联请求真实排空，不等待无关连接；辅助 Hub 调用不归到主模型账号。

验证结果：1172 项离线测试全部通过，0 失败、0 跳过；类型检查和生产构建通过。覆盖真实本机 HTTP、OpenAI SDK 的工具流、合成 OAuth/JWKS、并发刷新与登出、跨库恢复、用量事务崩溃注入、Windows Codex／Playwright 原生执行。独立浏览器夹具通过默认与覆盖保存、错误保留、桌面 OAuth 协调和窄屏交互检查。没有以这些离线结果代替真实账号资格、套餐授权或模型质量验收。

补齐了服务商默认思考强度的传输约束：SDK 入参及最终请求均清除遗留 effort，显式 max、ultra 保持原值。固定 Codex 版本的本机协议 schema 支持模型声明的非空强度字符串。

### 配置与实际请求核对

新增 [请求级端到端回归](../tests/model-routing-wire.test.ts)，经过真实 HTTP 配置入口、Mastra、现有供应商 SDK 和网络传输，再由隔离的本机模拟供应商接收并检查请求。没有以运行快照或界面标签代替发出的模型名、认证身份和思考参数。

| 路径 | 实际请求的核对结果 |
| --- | --- |
| 全局默认 | 跟随场景使用全局连接、模型和强度；更改后只影响新受理回合 |
| 独立后台默认 | 自主资料回顾使用后台配置，即使资料所属场景另有覆盖 |
| 后台继承全局 | 使用全局配置，不误用资料所属场景的前台覆盖 |
| 场景覆盖 | 使用场景保存的完整选择；全局改变不覆盖它；恢复跟随后用全局 |
| 排队及恢复 | 配置改变和重启之后仍发送受理时的模型与强度 |
| 工具续步 | 回合内全局设置变化不改变后续工具步骤的模型请求 |
| 辅助记忆 | Observer、Reflector 与当前交流使用同一绑定，不误走自主后台默认 |
| 获准异步任务 | 使用登记时的来源场景选择，后续场景及后台设置变化不改任务请求 |
| 项目中继 | 最终 Responses 请求采用原任务绑定，覆盖原生执行器附带的不同 effort |
| 连接失效 | 不向有效的全局或后台账号静默回退 |

覆盖 DeepSeek、自定义 OpenAI Chat Completions、OpenAI Responses 和 SIWC 四种协议。固定档位保持原值；服务商默认省略强度参数；DeepSeek 关闭发送 thinking.disabled，自动策略按既定规则发送实际 low 或 high。这里只验证请求参数正确送出，不把模拟响应作为真实模型能力或内部推理预算的证明。

检查发现并修复了旧版逐消息强度与新绑定快照不一致的问题：过去可能记录 max、却发出默认 low。旧版字段现在在受理时归入完整绑定；历史消息仅在新的派发中派生有效选择，不重写过去的消息或用量事实。任务以已登记绑定为准。
