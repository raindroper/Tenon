# 发布前的隐私检查

源码、测试和文档只使用合成资料、通用示例地址及公开的第三方资料。真实服务域名、账号、设备标识、本机路径、运维回执和私有研究记录保存在仓库之外。模型密钥、设备凭据、用户数据、构建产物和完整备份不进入 Git。

桌面发行者通过 `RAE_DESKTOP_PROFILE_FILE` 提供自己的私有构建配置，参见 [Windows 客户端](windows-desktop.md)。默认源码不指定发行者服务或更新公钥。更新签名校验不能因缺少发行配置而绕过。

发布前检查：

1. 审阅实际受跟踪文件、文件名、截图和元数据；区分通用示例与真实个人信息。
2. 运行 Gitleaks 检查当前内容及全部待发布历史。CI 使用固定版本和摘要，输出默认脱敏；例外只匹配已人工确认的非凭据字面量及其确切文件，不豁免整份测试或目录。
3. 单独核对网址、IP、邮箱、人员名称、账号、设备名称和绝对路径。凭据扫描器不能替代个人信息审查。
4. 检查作者、提交者、提交说明、分支、标签、其他引用及远端配置。需要发布干净快照时，从核验后的文件创建独立仓库，不复制旧 `.git`、忽略目录或工作树管理信息。
5. 不将开发目录直接整体压缩发布；`.gitignore` 只影响 Git，不会阻止压缩工具包含本机私有文件。

删除当前文件不能清除旧提交，也不能收回已经产生的克隆、fork 或缓存。历史清理及托管平台处理边界见 [GitHub 官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。仓库所属账号及发行站点本身也可能形成身份关联；源文件脱敏不等于匿名托管。
