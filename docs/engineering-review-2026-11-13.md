# 工程审查记录：2026-11-13

本记录说明运行时、HTTP 与连接器边界、桌面和 Linux 执行端、前端状态及发布流程的工程修复与验证范围，不包含实际部署实例和个人活动回执，也不承诺代码不存在其他缺陷。

## 已修复的问题

| 问题 | 修复及回归依据 |
| --- | --- |
| 并发关闭来源注册表可能重复关闭 SQLite，并继续受理新操作 | 关闭使用同一个 Promise；立即关闭准入，排空已接受的操作和 watcher。通过并发关闭及延迟登记测试。 |
| 来源扫描可能重叠或在停机后继续推进处理 | 只有来源扫描保持单次在途，停机等待其完成；慢扫描不阻塞已有提醒、回执和租约续期。确定性测试持有扫描 60 秒以上，验证提醒继续执行、扫描不重叠、关闭后不再调度。 |
| 项目暂停可能漏等正在登记的 runner，或漏等晚到的取消 | 暂停共用一个排空 Promise，暂停期间不受理新执行，等登记、runner 和已接受控制全部完成。覆盖登记竞争、晚到执行及晚到取消。 |
| 本地回执确认落盘失败后，内存仍可能认为已确认 | 确认游标先原子落盘，再更新内存，沿用原每操作串行队列。故障注入验证无需重启即可重试原回执。 |
| 原生 RPC 的非法对象或同步通知异常可能逃出事件回调；关闭漏等异步通知 | 校验协议对象，统一收集回调错误和在途回调，关闭等待实际排空。覆盖非法 JSON 对象、回调失败和进程退出后的延迟持久化。 |
| 内置执行器自动同步插件目录，遗留的 Git 子进程可能占用输出管道，使已完成任务无法确认关闭 | 按支持的配置关闭原生插件及推荐目录能力；通过内置版本的有效配置核对和真实原生用例验证。保留进程排空要求，未将超时或进程退出等同于所有操作完成。 |
| 邮件回执恢复可能重复追加正文、漏补确认或丢失回复关联 | 公开正文与恢复摘要在同一个 Store 事务中提交；跨库确认和结果证据可重复修复；保留原 replyTo。覆盖三个提交故障点及重复恢复零写入。 |
| 项目、邮件和 GitHub 结果证据的摘要受 JSON 字段顺序影响 | 新摘要按现有 schema 规范化；旧原生证据 ID 使用只读兼容校验，保留原记录。覆盖历史读取、篡改拒绝及重复恢复。 |
| 邮件附件绕过统一的登录失效处理 | JSON、multipart 和二进制响应共用前端会话与错误入口，删除独立附件错误解析。覆盖当前会话 401、旧会话迟到 401 和成功传输。 |
| 浏览历史时，实时回复可能回退到旧的流式正文 | 保留已观察到的消息、事件和运行回执；旧分页返回时与当前窗口合并。覆盖完成消息离开实时页及分页竞争。 |

## 删除与抽象

- 三处 HTTP 请求体读取合并到 `server/http.ts`；两套通用 HTTP 错误类合并为 `HttpError`，业务层 `RuntimeInputError` 保留原职责。断开连接、格式失败和分配异常通过同一入口处理。
- 删除 HTTP 请求体的固定字节上限，包括 Windows/Linux 共用的本机模型转发通道；后者的重复读取函数由 Node 自带的流读取入口替代。AR 的 Nginx `client_max_body_size` 设为 `0`。具体业务字段、图片解码和邮件附件的既有有效性规则仍由相应 schema/适配器负责；移除传输上限不表示内存、磁盘或上游服务具有无限容量。
- 删除未使用的导入、参数和辅助函数，启用 TypeScript `noUnusedLocals`、`noUnusedParameters`，纳入现有 `check` 和 `build`。
- 原生执行器启用 `--strict-config`，删除原来被静默忽略的 `model_supports_reasoning_summaries` 和 `windows.require_mxc`。Windows 仍使用实际 MXC 沙箱。关闭插件的依据包括[官方配置文档](https://learn.chatgpt.com/docs/enterprise/managed-configuration#configure-network-access-requirements)和本项目固定版本的有效 feature 列表；没有升级或修改上游执行器。
- 静态导入引用检查中，无入边的源码模块均核对为应用、preload、worker 或构建脚本入口；没有据此删除动态入口。桌面打包实物核对 28 个包、31 条依赖边，未发现版本替换，保留现有打包方式。
- Windows 打包改用 electron-builder 支持的 `electronDist`，复用已安装的 Electron；先核对其实际版本文件与项目固定版本一致，避免重复下载和重复维护版本号。依赖源目录采用复制，不作为可变打包输出。

没有新增执行入口、框架或依赖；没有更改任务授权、来源访问范围、模型预算及 Hub 视频串行规则。没有改写或删除历史数据。旧证据摘要兼容仅负责读取历史，不构成第二套执行实现。

## 验证与发布

此轮源码的 `npm test` 共 **1097 项通过，0 失败、0 跳过**，用时约 128 秒；`npm run check`、`npm run build` 和 `npm run desktop:package` 通过。实际 Windows 原生用例完成代码修改、Node 检查、浏览器交互、截图上传及父子进程排空；没有延长既有关闭超时。

测试使用隔离临时数据和 Node 网络保护。此次发现原生 Git 子进程不受 Node socket guard 约束，已在原生夹具中额外禁止远端 Git 协议，并核对真实引擎的有效插件开关。故障回归使用可控门控与注入点，不调用真实模型。

发布需要遵循备份、暂停排空、候选验证和版本指针切换，参见[通用部署说明](deployment.md)。实际上线时间、版本摘要、设备状态及回滚位置由部署者私下记录。

- 前端主 chunk 仍约 612 kB，构建保留大于 500 kB 的提示。后续可按实际加载与缓存收益拆分，不能仅调高告警阈值作为优化。
- 项目级开源许可证仍未确定，见 README。此次没有替所有者选择许可证。
- 本轮验证覆盖协议、持久化、授权、恢复和界面状态机制；不证明真实模型的理解准确率、长期能力增长或所有桌面应用的操作效果。
