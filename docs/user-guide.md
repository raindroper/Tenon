# 榫 Tenon 使用指南

榫是应用的中文名，英文名为 Tenon。旧版默认的助手称呼 Rae 随升级显示为「榫」，其他已保存的自定义称呼和对话原文照常保留。

本文承接原 README 中的详细操作说明。产品定位与行为边界以[当前产品契约](../README.md#当前产品契约)为准；首次安装见[快速开始](../README.md#快速开始)。文中的命令与配置路径以仓库根目录为基准。

## 网页登录与公网入口

公网网页使用单个内置用户登录，不提供注册。配置`RAE_PUBLIC_ORIGIN`时必须同时设置`RAE_AUTH_FILE`指向私有用户文件；缺失或无效时启动失败，不能退回免登录。凭据只保存带随机盐的`scrypt-v1`摘要，会话使用独立SQLite数据库、7天绝对有效期及HttpOnly/SameSite=Strict Cookie，公网另加Secure。退出会撤销服务端会话，更多菜单可退出登录；失效后清空当前页面快照，不自动重放操作。未配置公网入口和用户文件的本机开发保持直接访问。

登录先校验请求结构，再进入有限并发的密码校验。通过本机反向代理访问时，应用只看到共享回环地址，公网按来源限流需由入口代理提供。应用不采用客户端可自行填写的转发地址。

维护者可使用`scripts/set-web-user.ts <私有文件绝对路径>`生成或更新内置用户文件，标准输入为`username`与`password`的JSON；密码至少12位，不通过命令行参数或日志传递。Linux文件应为0600，或root与服务用户专属组的0640；文件不能放在静态目录、仓库或模型资料中。设置`RAE_AUTH_FILE`后重启应用生效，更新凭据会使旧会话失效。公网入口和部署操作见[部署说明](deployment.md)。

## 模型连接与默认配置

从 0.1.25 起，「更多 → 设置与连接 → 模型连接」可以保存多个自定义 API 连接和多个 ChatGPT 账号。添加连接不会覆盖已有连接，也不会修改当前默认。榫的网页登录与 ChatGPT 模型授权分别管理。

- **自定义 API**：点击「添加 API 连接」，填写名称、Base URL、API Key 和接口协议。支持 DeepSeek 兼容、OpenAI Chat Completions 兼容和 Responses 兼容路径。按服务商实际接口选择协议；已有连接的协议不能就地更换，需要新增独立连接。模型目录可手动获取，接口不提供目录时可以填写真实模型 ID。
- **ChatGPT 账号**：点击「连接 ChatGPT 账号」，填写便于区分的名称，再点击「Continue with ChatGPT」，由本人在浏览器完成授权。每个注册独立保存，可以在不同场景中同时引用不同账号。完成后获取该账号的模型目录，再保存默认或场景配置；登录成功不等于已获套餐模型调用权限，界面会分别显示。
- **远程首次登录**：使用 0.1.25 或更新的 Windows 客户端打开同一榫服务。客户端辅助接收本机 OAuth 回调，榫后端完成换码和凭据保存；普通远程网页目前不能完成首次回调，但可以选择和管理已有账号。本机 `localhost` 或 `127.0.0.1` 网页可使用本机回调。详见[桌面 ChatGPT 登录](windows-desktop.md#chatgpt-模型登录)。

保存设置、登录和读取目录不调用推理模型，也不打开「开启自主学习与交流」。连接卡片的「测试连接」需要本人选择模型后点击「发起一次测试」，这会实际调用模型；接口、工具或账号可用性不能仅由登录或目录成功证明。实际可用模型、档位和授权以当前连接为准，不把离线回归当成账号实测。

默认项和场景选择都保存完整的“连接、模型、思考强度”，并按适用协议保存可选输出上限：

| 配置位置 | 使用范围 | 全局默认变化后 |
| --- | --- | --- |
| 全局默认 | 未单独配置的普通场景 | 后续新回合使用新值 |
| 后台默认 | 新的自主后台分析；可以独立配置或跟随全局 | 仅选择跟随时一起变化 |
| 对话中的场景配置 | 当前场景的新回合与新委托 | 显式覆盖保持不变；恢复跟随全局后重新继承 |

“跟随全局”保存的是继承关系。场景显式选择的值即使与当前全局相同，也仍是覆盖，刷新页面和重启后不会丢失。设置页的两个默认项分别保存；模型连接的保存与页面下方「保存常规设置」相互独立。出现版本冲突时重新打开对应编辑区核对，避免覆盖另一窗口的修改。

在输入框旁打开「＋ → 对话选项」，可选择执行设备，查看和修改场景的模型连接、模型与思考强度，或勾选「跟随全局默认」。已指定的设备和需要处理的模型连接问题会显示在输入框旁。保存用于当前场景之后的新回合；已接受的排队消息、已经开始的回合和任务保持原配置。任务转入后台、关闭网页或在其他场景继续查看，不会改用后台默认。当前界面不再提供发送后重置的逐消息思考草稿；旧消息已经保存的单次强度仍可显示与回查。

思考选项来自对应协议和模型能力。「服务商默认」表示省略该参数，与榫的「跟随全局」不同。DeepSeek 连接保留原来的自动策略；其他连接不把未知档位映射成同名能力。更换模型后原档位不适用时，需要重新选择。自定义 API 可填写适用的输出上限，SIWC 使用接口默认限制。

连接失败时，卡片保留最近的脱敏原因，原选择、对话和进展保持不变。可以修复原 API key、重新登录同一 ChatGPT 注册，或为全局、后台及某个场景手动更换完整选择；也可以明确恢复跟随全局。一个连接出错不会停用其他有效连接，不会自动轮换账号、模型或计费来源。临时网络故障、用量限制、模型不支持和凭据失效分别报告；token 正常到期由后端续期，不能把续期等同重新选择账号。

修复连接不会自动重新执行失败消息。需要继续时，明确点击原消息的「重试这条」；若原回合已受理工具操作，或账号、地址等身份范围已经变化，按提示核对已有结果并用新消息继续。修改默认或场景选择用于新回合，不会热切换旧任务。退出 ChatGPT 账号保留连接引用；远端撤销未确认时保留提示，可在 ChatGPT 设置中断开应用。

API key 和 OAuth token 加密保存在榫后端，不放入浏览器存储、普通导出或项目执行器环境。连接旧实例时迁移原接口与凭据，不从 Codex CLI 登录缓存读取 token。原环境变量密钥仅绑定迁移连接，不作为其他连接的通用后备。

## 场景与对话

页面以单列持续对话为中心，顶部 Tab 直接切换场景，旁边可新建；场景较多时横向滚动，左右方向键移动焦点、Enter 或空格切换。新场景从八组主题色中随机分配，优先使用尚未分配的颜色；页面使用冷白底色，背景、按钮和气泡保留轻微的场景色差，刷新后保持主题。“更多 → 管理场景”可查看已停止场景，场景详情可编辑名称和背景。“通用”沿用原主对话的记录；已有主题沿用原 ID、历史、资料及任务归属。普通聊天可直接新建场景，背景可留空。输入框旁“＋”可添加图片、资料或明确委托；待确认任务出现在所属对话中。委托和媒体生成默认沿用当前可用场景，也可明确选择新建。切换时保留各自未发送的文字、图片，以及已保存的场景模型配置。布局及交互验收见[界面验收](../design-qa.md)。

连续回复各自独立排版，消息之间用留白区分，同一条消息的流式更新保留在原处。鼠标移到消息上、使用键盘聚焦或在触屏查看时，可引用或评价对应消息。短表格直接随正文展示，也可展开阅读；较大的表格和较长的多段文档节显示为阅读入口。点击“阅读”查看完整原文，可放大面板、复制内容；宽屏使用右侧留白，窄屏覆盖显示，关闭后回到原入口。流式回复先保持连续显示，代码示例和依赖外部引用定义的内容保持内联。阅读不会改写或重新生成消息。入口与面板提供轻量过渡，系统开启“减少动态效果”时停用动效。

也可以直接通过对话操作产品：新建、改名、修改背景、归档或恢复场景；查看、保存、纠正、撤回或恢复记忆；查看、连接、同步或断开连接器。普通操作以当前本人的明确指令为准，无需二次批准；能力询问、讨论、外部资料和自主建议不构成操作许可。对话复用页面使用的同一 `RuntimeApi`，不新增另一套业务状态或执行框架。

例如「从我们聊过的工作内容中整理背景，新建一个工作场景」，榫会按相关本人原话回查并整理背景，保存出处，原对话不搬家。背景是可编辑的快照，不能把助手建议当成本人事实，也不声称穷尽所有历史；缺少的信息留空或注明待确认。场景详情可查看出处及来源场景。引用的原话被记忆纠正或撤回后，自动背景不再进入后续推理，已保存文本仍可查看与导出；只改名不移除出处。

「删除场景」默认归档：移出活动列表，保留历史且可恢复，停止原场景的任务和提醒。正在查看的归档场景仍可阅读，通用入口保留；恢复不会重启旧任务许可或提醒。记忆撤回保留历史版本，恢复需明确选择版本。OAuth 连接会给出登录入口，实际账号授权仍由本人完成；腾讯文档可使用已保存的凭证连接明确指定的文档，密钥只在连接器面板填写。缺少平台配置或凭证时如实提示，不能冒充已连接。

产品操作先保存当前消息绑定的指令，模型回合结束后由原生接口执行，真实结果写回原对话；「已受理」不代表完成。同一消息和工具重复提交不会重做。重启遇到未开始的操作标明未执行，遇到已经开始但缺少回执的操作标明结果未知，均不盲目重放。取消或关闭会等待已接受的操作及回执结束。实现与验证见[对话产品操作说明](conversational-product-controls.md)。

场景配色保存在原生场景元数据的 `themeId` 中，无单独的浏览器配色副本。升级时只为旧场景补齐稳定配色，通用场景保留鼠尾草绿，不改动名称、时间戳、对话或工作记忆；配色随现有完整导出和数据目录备份保留。旧的右上角下拉切换入口已由顶部 Tab 替换。

正常与榫交谈，或在“资料来源”添加不超过200KB的UTF-8 TXT/Markdown/JSON。未选择场景的新消息进入“通用”（原“相处与成长”，ID 为 `personal-growth`）；点“回复这条”会继承原消息的场景。每轮先加载当前场景背景，再由榫按需查找相关历史。普通相处与学习直接进行。

当前页面为一次消息提交保留同一个请求编号。服务端已保存、响应却断线时，直接重发未改动的草稿会返回原消息，不再创建第二个处理事件；修改内容、图片或范围则视为新提交。旧版无请求编号的 API 调用仍按独立消息处理。

榫回复时仍可发送新消息。同一场景的新消息会等当前回合结束后处理。想提前结束当前回复，可以点发送按钮旁的「停止回复」。已收到的正文会保留，已经受理的操作会结算并写回实际结果。当前回合结束后，排队的消息继续处理，后台委托仍可在任务卡上管理。

超出近期上下文的消息仍保存在原场景。直接回复旧消息时，本轮带入同场景原文片段和可用的引用图片。需要回查时，榫通过 `recall` 按关键词及语义查找本人原话，默认查当前场景，必要时可跨场景。每次搜索最多返回五条摘录，附场景标题、时间和消息 ID，也可带上较新的本人原话供核对变化。需要更多内容时，榫可按本轮已找到的消息 ID 分页读原文。相似度用于找线索，当前决定以本人最新表达和有效记录为准。

本人可以在另一场景找回同一任务、查询实际结果，或给仍在执行的原任务补充要求与已授权资料。榫按需查找已有来源，再把具体原始事件关联到任务；资料不搬家，文件和账号权限不扩大。任务保留原归属和同一个编号，在本人明确续接的场景也显示同一张任务卡。长交付物可按页回读；旧要求版本不会冒充当前结果。已经结束的任务可回查，新的产出仍须明确委托，不自动复活旧许可。

关联资料及任务实际读过的来源都会保存出处。停用或替换来源后，后续任务、结果回查与方法学习重新核对有效性，不能从旧工具结果、派生交付或反馈快照绕回已撤回的正文。本人已收到的历史和产物继续可查看、备份及导出。外部群聊、邮件或文档内容始终是资料，不能变成本人的执行指令。

聊天默认显示当前场景最新 40 条消息。向上滚到顶部或点击“更早消息”时，旧消息会接在上方，当前阅读位置保留。点击“回到最新”可直接跳到最新消息。场景列表保留简短预览，生成面板仍可读取当前场景较早的参考图，完整聊天与图片可从导出中获取。

运行记录和事件记录每页显示40条，可用“更早记录”“较新记录”“回到最新”浏览全部历史。聊天实时状态只附最近活动和当前消息页对应的处理状态，旧消息的失败原因及重试入口仍然保留。导出包含全部运行和事件记录，不受页面条数限制。

正在处理的对话和获准任务会显示一行进度，例如“搜索 GitHub 仓库 · 进行中”，旁边显示实际用时。点击可展开本轮真实工具操作、状态、简短结果及各步耗时；默认只展示最近几项，可继续展开更早操作。回复完成后，有操作记录时可从正文下方展开；失败和待核对状态保留说明。有本轮来源回执时，可展开查看实际引用的事件记录。刷新和断线重连读取已保存的过程。较早版本没有采集的过程不会补造。

从 0.1.28 起，一项任务可以包含需求梳理、具体邮件审批、等待答复、继续项目和本人验收。已授权文档出现相关变化时，榫可以提出完整项目目标；你在原卡片选择设备和工作区后开始。Windows 也可以在对话中明确指定原提案的执行范围。项目执行需要更新后的客户端或 Linux worker。

缺少信息时，问题及其影响的步骤保存在原任务里。你可以在问题卡填写答案，也可以在原场景对话中回答。榫需要向外部人员澄清时，先准备具体的 EWS 邮件正文、收件人和附件供你核对，批准后才发送。同组问题可以分别准备给产品经理、后端等不同对象的邮件，每封单独审批并关联各自的回复。相关回信经过来源和内容核对后接续原任务；部分回复或相互冲突的回复继续保留缺项。回信可以引用当前已授权的资料，榫可在原范围内只读查证。外部答复不能增加目标或资源权限，也不能覆盖本人明确给出的答案。

自动关联回信需要真实原信标识及匹配的收件人范围，不仅比较主题。邮件服务未返回可靠标识、回复来自其他发件人或无法确认指向时，问题卡保持等待，可以由你补充答案。Gmail 和 Outlook 连接器仍是只读观察，发信闭环使用已有 EWS 能力。

等待会释放执行进程，保留任务进度。恢复前会核对实际文件，发现期间被修改时先请你确认。新 Linux 委托在资源确认卡中另外列出持久检查点的文件上限，工作区可跨等待及执行端重启恢复；历史临时空间许可不会自动扩大。需要本人验收的任务会保留继续修改所需的工作区，验收或停止任务后释放。已确认结束的旧任务不会被新回信重新启动。

服务器任务完成后，任务卡会显示已保存的文件，可以逐个下载或选择“全部下载（ZIP）”。成果文件独立保存，验收并释放运行工作区后仍可下载。仍有保留工作区的旧任务可以点击“领取文件”，读取已有成果，不重新执行任务，也不需要开启推理。通过留存副本恢复的历史文件会注明恢复来源与范围。[服务器文件交付](project-file-delivery.md)

“等待模型响应”“等待操作返回”与“连接恢复中”分别表示不同状态。连接心跳不算工作进展；一分钟没有新活动仅提示等待较久，不停止任务或自动重试。进度由既有运行时事件生成，不额外调用模型，也不展示完整思考、原始工具参数或私有响应正文。后台资料回顾不会冒充当前消息的答复进度。

从「＋ → 添加文件」选择附件，也可拖入输入区或粘贴剪贴板里的文件。可以只发附件，或附上具体问题。普通文件保留原始字节，每条消息最多 4 个，单个最多 10 MiB，合计最多 20 MiB，发送后可从消息下载。

榫能读取本条消息或所引用原消息里的 `.xlsx`、UTF‑8 文本、Markdown、CSV、TSV、JSON、JSONL、日志、XML、YAML 和 TOML。大型文件只读取有限摘录；Excel 摘录包括工作表名和单元格地址，公式使用工作簿保存的缓存值。PDF、Word 等其他格式仍可收发和下载。启用推理时，本轮用到的摘录会发送给所选模型；文件名和内容只作为资料。

PNG、JPEG、WebP 通过同一入口发送。浏览器在本地缩放至最长边 2048 像素并按需压缩，最多 4 张、单张 512 KiB、合计 1 MiB。每轮最多带入 4 张且合计 1 MiB 的近期或引用图片。图片识别需由所选模型及网关支持。

联网搜索复用现有Hub的HTTP联网功能：服务器配置`RAE_HUB_SEARCH_URL`且Hub面板开启“本地网络工具”后，模型可按需调用`web_search`。没有新增搜索服务或付费搜索API，也不读取或修改Hub源码。Hub内部可搜索、阅读并整理资料，返回的是带来源的网关摘要，不能当作网页原文或直接写成本人偏好、独立方法证据。摘要按事项保存在既有事件中，引用与失败原因可追溯，不额外触发一次学习或推理。浏览器交互、登录网页和独立的原文抓取未接通。

图片和视频生成复用Hub现有媒体接口，配置`RAE_HUB_MEDIA_URL`后可在“＋ → 生成图片/视频”直接选模型、填描述，提交即授权。聊天里“做张活动海报”“把这段故事做成短片”等明确制作请求，由当前对话模型理解并登记一次媒体任务；不增加独立分类模型，也不要求固定关键词。仅询问能力、讨论方案或代理自己想做时不能直接生成，拿不准先询问。媒体参数和参考图绑定原场景及真实许可；文生图、改图、文生视频、上传参考图生视频按网关实际能力标签选择。

生成由上游完成，服务端只提交、查询并流式保存产物，不安装生成引擎或GPU软件。视频在后台按原Hub任务ID查询，进度与图片/视频预览、下载显示在原对话卡片；无须模型反复等待。生成POST前保存记录，超时或重启不能确认受理时标记未知，不自动再花额度重做；收到来源或视频ID后只查询/取回原产物。上游开始的任务可能无法取消，取消不保证停止生成或退回额度。数据目录的`media/`保存私有产物，JSON导出含任务元数据，媒体文件单独下载或随整个数据目录备份。

当前 Hub 版本的共享文件名需要串行处理视频。已保存私有文件、明确未提交或上游确认失败且无产物时，下一笔才能开始。取消后仍可能生成的任务会按原编号核对。丢失编号或产物无法取回时，后续视频保持等待，任务卡会给出原因。对话和图片任务仍可处理。

Hub检索可能额外调用模型，沿用其现有流程；只认可真实搜索事件与网关引用，模型自行编写的链接不算查证成功。中间模型用量未完整回传时，本轮显示已知token并明确标为不完整，不虚报完整总量。Hub 搜索与媒体保留独立的服务地址和凭据，搜索地址只与该 Hub 连接的 Responses 端点核对，不跟随全局或场景模型切换；ChatGPT OAuth token 不发送给 Hub。取消和超时停止当前请求，不盲目重试同一句。

### 连接器

#### 自建 Exchange：服务端 EWS 邮箱

在服务端运行 `npm run prepare:ews` 并重启服务后，在连接器中选择“企业 Exchange（EWS）”，绑定场景，填写公司提供的 HTTPS EWS 地址、已确认的登录名和密码。需要读取 S/MIME 加密邮件时，上传包含私钥的 PFX/P12 并填写证书密码。确认保存凭据、观察收件箱新邮件和分析正文后连接。登录名可以是公司确认的 UPN 或 `域\用户名`，邮箱域名不一定等于登录域。

读取、解密和同步都在榫服务端完成，支持 Windows x64 和 Linux x64。凭据加密保存，重启后恢复原连接与同步位置；“更新密码或证书”保留原范围，失败时保留旧凭据。断开后停止观察并删除该连接的凭据，历史资料保留。仅获取连接后收到的新邮件正文，初始游标建立只检查旧邮件元数据，不回读旧正文；不发送邮件或修改已读状态，不下载普通附件。

邮件正文会保存为外部资料，可由现有 `read_event` 分页回查。超长邮件、未配置或不匹配的证书、不能解密或解析的内容会明确说明实际读取范围。暂停推理仍可同步，连接不会自动打开模型。私钥不会发送给模型，解密不等于验证邮件数字签名。

连接器中可“写邮件”，在邮件详情可回复、回复全部、转发，以及查看和下载附件。发信前填写真实收件地址，核对实际正文与附件；点击“发送这一封”即委托当前任务执行器提交。也可在邮箱所在场景明确委托榫撰写并发送。每个文件最多 5 MiB，每封最多 10 个且合计 10 MiB。当前发出的是明文邮件；加密原信的回复或转发须明确允许以明文分享，自己的解密 PFX 不能替代收件人加密证书。只有服务器确认才显示已提交，结果未知时不会自动重发。部署、备份和具体限制见 [EWS 连接器说明](ews-connector.md)。

现有 EWS 连接还可点击“查看邮件”，立即列出、按主题查找并读取收件箱已有邮件，包括连接前的邮件；读取加密邮件会使用已保存的证书。也可以在绑定场景直接要求榫：“列出最近10封邮件”或“按主题找某封邮件并读取”。这些按需查询不会改变自动观察的起点，不用等待基线建立。列表和正文均可分页，过期结果或更新凭据后需重新查询。

在浏览器打开「更多 → 连接器」或「设置与连接 → 管理连接器」。GitHub 按账号接入，无需绑定单个场景或仓库；其他平台选择场景和观察范围。腾讯文档先在「腾讯文档令牌」保存个人 Token，再选择已保存的令牌添加文档。其他平台按各自的授权流程连接。桌面客户端的 OAuth 在同一榫地址的系统浏览器里完成。面板可以检查最近同步时间、手动同步和断开连接。

观察类连接首次建立基线。腾讯文档后台约每 30 分钟检查一次，其他轮询连接约每 5 分钟检查增量，积压时继续分页。需要提前检查时可点「同步一次」。上游限流遵守其 Retry-After，限流期间手动按钮也不会反复请求；授权撤销、过期或权限被拒绝时暂停自动重试，面板显示“需要处理”。Gmail/Outlook 可在原连接重新授权，核对仍是同一邮箱/文件夹后保留原连接 ID 和同步位置；GitHub 账号连接不参与全仓库自动轮询，可在原连接更新令牌或检查账号状态，凭据版本变化仍使旧任务许可失效。暂停推理时仍可采集，连接不会自动开启推理。

#### GitHub 账号搜索与仓库操作

账号接入可在所有本人场景使用 GitHub 官方 MCP，按需搜索账号可访问的仓库、代码、Issue 和 PR，再读取相关文件或事项。可以直接询问“找我能访问的订单服务仓库”或“搜索这些仓库中的相关实现”，无需先添加每个仓库。连接不会主动穷举所有仓库，也不构成自主写入委托。

令牌决定实际可用权限。使用 fine-grained 令牌时，可在所选 Resource owner 下选择 All repositories，并按需授予 Contents、Issues、Pull requests 权限；这个选项只覆盖该用户或组织。跨多个组织或外部协作者仓库时，可能需要 classic 令牌及 `repo` 权限。组织审批、SSO、私有仓库策略和你本人的权限始终生效，令牌不能授予本人原本没有的能力。[GitHub 官方令牌说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) 令牌加密保存在服务端，不发送到聊天或模型，也不写浏览器存储。

在任一本人场景中明确委托，并说明目标仓库，例如“修复 `owner/orders` 的登录流程，提交到 `feature/fix` 分支并建草稿 PR”或“更新 `owner/site` 的 Issue #12 描述”。榫使用同一 `request_task` 和任务执行器登记目标，绑定实际仓库、账号及凭据版本和目标分支。本人已明确限定的文件、Issue/PR 编号和可修改字段继续保留；没有逐文件限定时，按任务目标处理本次仓库/分支中的文件，普通范围内步骤不重复审批。外部代码、Issue/PR 内容和账号连接本身不能自行授予新的任务许可。

工具直接来自 GitHub 官方 MCP，当前支持按任务目标提交代码（本人明确列出文件时保留该限定）、Issue 创建/修改/评论、草稿 PR 创建及 PR 标题/正文/状态修改。操作前持久记录提交意图，成功后保存 GitHub 返回的 commit SHA、编号和链接；相同调用去重，结果未知时保留未知并停止后续写入，不自动重发。每项任务的单次 Issue/PR 创建不因模型改写内容或补充要求而变为无限创建。任务详情显示本次目标范围和实际回执，不用模型文字代替提交事实。

当前没有本地代码编译或测试环境，不能把“能提交代码文件”当成完整通用编程工作台。仓库删除、强制推送、PR 合并、账号权限管理、Actions 写入和 Copilot coding agent 不在这次工具集合中。旧单仓库连接和历史资料仍保留；在连接器中明确确认“升级账号接入”后，使用已保存的凭据核对账号，不回显令牌。升级不会给旧任务扩大许可。

在对话中明确要求查看或筛选已连接的腾讯文档时，榫可按需读取该文档当前返回的正文，即使还没有同步变更。只有一份连接时可直接读取，多份时按标题或链接识别。表格结构和列名可核实时，可在指定列查找关键词并返回命中行和表头。缺少可核实的列结构时会注明范围。查询的原始工具结果不会在后续轮次重复发送。此读取受原连接范围和正文读取上限约束。

连接凭证只保存在服务端私有数据目录，Windows 使用当前用户 DPAPI，Linux 使用 AES-256-GCM 和同目录的仅属主可读写密钥文件。断开后停止后续观察，历史事件保留供追溯。腾讯文档令牌独立保存，断开一份文档后仍可用同一令牌添加其他文档。断开所有使用某枚令牌的文档后，可单独移除该令牌。升级时保留原文档连接及游标，将相同的旧令牌合并保存。Gmail 与 Outlook（Graph）观察保存有限预览，附件和完整正文不进入事件；EWS 按上述授权保存有界正文，不下载普通附件。

Windows 桌面客户端可通过本机加密数据库观察已登录的官方微信。在托盘「本地设备与授权 → 微信会话观察」按群名、联系人名或关键词筛选会话，勾选并绑定榫场景，最多保存五个会话。v0.1.7 保存加密断点和待上传批次，提供历史范围、独立暂停恢复、消息样本及分析状态。榫可在普通对话里按会话名称、时间、发送人查询已收内容。微信自动分析默认十分钟合并，完整分页处理积压，任务继续由本人批准。 [Windows 桌面说明](windows-desktop.md#微信会话观察)

榫从已授权的微信会话发现值得提醒的会议邀请时，可以在对话中显示会议卡片。卡面显示会议时间和来源，邀请提供会议号时可以一键复制。展开依据可查看提醒原因、推测和待确认事项。旧提醒和信息不足的提醒继续以正文显示。

网页 Agent WeChat 扫码试用已退役。已有试用记录保留在数据导出中。 [历史调研](../research/agent-wechat-research.md)

场景保存各自的交流背景，任务另按本人许可执行。“对你的理解”和“我的方法”分别显示本人理解与代理方法；两者都有证据、范围和可纠正版本。每轮会附带少量适用的最新更正或撤回状态，帮助区分历史说法与现行理解。保留版本中的同一主体、事件和逐字摘录已被纠正或撤回时，换记忆键也不能将该旧证据重新写入；同义改写及已存在的别名仍需后续核对。方法可从真实教导、授权资料或对回应的评价中积累，反馈形成的经验继续标为待验证。“资料来源”区分目录与上传文本；“运行记录”区分成长和任务执行，成果继续标记待验收。

任务结束时，本地程序把实际交付、认证设备回执和工作区检查关联到原任务及要求版本，不额外调用模型。本人评价任务结果时，反馈绑定服务器保存的目标正文和结果引用；已有交流或反馈回合可据此修订方法。方法详情会分别显示本人评价和具体检查：“文本已保存”只证明保存，“退出码为零”只证明该次操作，均不把方法自动认证为可靠能力。已撤回来源的旧目标反馈继续保存，但不再借其正文触发学习。原始依据、纠正版本和历史仍可导出。

本人对话积累到一定长度时，榫会用 Mastra 的观察记忆整理已核验的本人原话，并在后续对话中按需使用。观察和回复共用本轮步数、时间和用量记录，并为回复留出一次模型调用。更正、撤回或缩小范围后，已识别为过时的派生观察及索引会重新构建，原始消息和记忆版本仍可查看或导出。排除旧证据的精简依据保存在原有个人核心中，独立于八版可恢复历史，并只影响其实际来源或原适用范围；无新观察的普通回复不会重写索引。没有来源关联的旧值按逐字匹配识别，同义改写仍需后续核对。

来源变化先进入统一的有界回顾队列。普通来源默认五分钟合并，微信使用本人设置的分析间隔，各来源公平处理。每条资料保存批次归属，超过一页的资料继续排队；没有新信息时等待。榫结合本人要求和既有事项，判断是否有值得告知或可以提供的具体帮助。提议前可只读调研当前场景已授权的腾讯文档、EWS 邮箱、GitHub 账号及已有微信/公开资料，读取保留来源回执。尚缺必要资料时先调查或询问；有可执行的具体帮助时显示提案卡，正式交付在本人批准后进行。已知事项可以先静默保存，再由新证据接续。明确的未来回顾只触发一次，已有日常提醒继续由本地程序直接投递。

“开启自主学习与交流”恢复既有队列和正常观察时间安排。需要提前回顾时，可通过独立控制 API 发起。没有新线索或定时安排时会等待，标题下显示实际等待原因或下一次计划，详情按需查看运行记录。设置中的步数上限用于后台分析和对话中的记忆整理，新安装默认 20 步。来源回顾预留最后一步收尾，需本人补充信息时会明确提问。已排日常提醒在暂停推理时仍会本地投递。

设置表单只提交实际修改的字段。启停变更绑定打开表单时的控制版本，旧窗口不能覆盖另一个窗口后来做出的暂停或恢复；遇到冲突需重新打开设置确认。直接调用 `/api/settings` 修改 `enabled` 时须携带当前 `expectedEnabledRevision`，明确暂停或恢复可继续使用 `/api/control`。

模型与思考强度按[全局、后台和场景配置](#模型连接与默认配置)确定，每轮保存实际请求的选择与来源。DeepSeek 的“自动”策略对实质问题、上下文续问、学习和获准任务请求 high，仅无上下文、无引用或图片的新会话独立寒暄请求 low，不额外调用分类模型。参数是否被上游采纳与答案是否正确仍需核对，更高强度不会增加工具权限。

回复正文从模型流式接收并分段保存，逐步显示在同一条回复中；思考过程不进入公开正文。断线重连后同步已保存的状态，不重新执行任务。适用的单次输出上限在完整模型配置中填写，默认留空；SIWC 不提供自定义上限。达到长度上限且有正文时可无工具续写一次，沿用原有的执行限制。本人对话、新委托及有本人来源的定时回访默认没有总步数或总时长上限，可用暂停或任务取消主动停止。已捕获的历史任务限制和单次请求超时继续生效。被动自主回顾继续采用有界处理。

仍未完成时明确显示“本轮未完成”，保留正文和实际保存的提醒回执，不虚报交付完成。后续故障或中断若已有正文或工具活动，不自动重放；旧记录已经明确保存的有限期限不因恢复而刷新。真正失败的本人消息旁可点“重试这条”，只恢复原事件并携带已保存安排供核对；暂停时仅排队，历史用量不重置。进程重启将旧的生成中回复标记未完成，原文保留，其他未受影响的新消息可继续处理。

普通交流或计划可直接回复。清楚的本人委托直接登记目标、交付范围与能力，后台执行普通步骤；自主提出的工作显示待确认任务卡。普通提案可点击卡片决定，也可在对话中明确同意或拒绝，任务、资料依据和此前决定保持同一份记录。文件任务仍绑定实际仓库和有效文件许可。原生目录查询可与文本交付组合，单次查询成功不等于整项任务完成。拒绝或撤销后不可再用原许可执行。

修改项目、运行测试或处理本机文件时，默认使用项目所在的 Windows 客户端；远程观察、收信和提醒继续在服务端运行。榫会参考当前场景已确认的项目位置；目标不清楚时询问真实目录，不用空白工程代替。你仍可在消息或下拉框明确另选设备，独立实验也可明确选择临时工作区。客户端离线或需要更新时，任务等待同一台设备，恢复后接着原进度做，不会自动转到服务器。服务器独立任务仍要在原任务卡确认工作区、网络和资源范围。 [项目执行与资源范围](local-project-harness.md#执行路径与权限)

项目执行会使用已有且已授权的开发工具，并核对项目要求的版本、依赖和必要后端连接。普通检查不重复询问许可；工具或后端不可用时说明受影响的验证，不假装已经通过。需要安装系统工具或扩大访问范围时再由你明确决定。

在「更多 → 我的设备」可以给已配对的 Windows 电脑修改名称，离线时也可以改。改名保留配对、授权和执行记录。保存后可以在对话里说「用指定设备执行」。

同一场景可以在任务执行期间继续交流。榫可读取真实任务进度，按当前本人原话记录范围内的补充要求，并停止旧要求的模型交付；原设备查询参数不变时继续核对同一操作，已受理的操作不重复提交。新要求沿用原期限和剩余步数；旧版本结果不能完成新版本任务。更换设备、目录、媒体参数或扩大目标需要新的对应许可。停止先阻止后续调用，再等待已接受操作排空；回执未知时如实说明。

关闭网页后，后端仍处理已保存的时间安排。暂停推理会停止新的成长/执行模型调用，但已排本地提醒仍可按时入箱；退出后端、电脑睡眠或关机时无法准时运行，当前没有手机或系统推送。重启保留未撤销的原任务许可，但不声称能从任意工具步骤无缝续跑。停止场景会取消该场景的提醒、学习回访和获准任务，包含已到期但仍在队列中的时间安排。需要继续收消息或委托时，请先显式恢复场景。目录采集需另行停用。

## 数据与用量

数据默认在`data/`，可用`RAE_DATA_DIR`修改目录。`rae.sqlite`保存设置、模型连接与选择、面向用户的记录及图片二进制（`message_images`表），消息与图片在同一事务保存。旧库自动补齐图片表和场景消息索引，沿用原有消息记录。`v2-events.sqlite`保存事件、来源、个人记忆版本账本、回顾决定与投递journal。`v2-memory.sqlite`保存原生场景历史及可重建的观察和向量索引，旧个人核心仅供迁移归档。`model-credentials/`保存受保护的模型凭据版本，`workspaces/`保存授权工作树与回执。备份整个目录。`data/`、`.env`不纳入版本控制。Windows 使用当前用户 DPAPI，Linux 使用加密文件及所有者密钥；状态与普通导出不返回密钥。环境变量凭据只对其绑定的旧连接优先。

消息幂等记录位于同库的 `owner_message_requests` 表，与消息、图片及 `message_files` 表中的普通附件原子提交。升级时自动补齐附件表，旧消息和现有设置继续沿用。启停版本保存在 `settings.enabledRevision` 元数据。

导出 JSON 包含当前运行数据、个人理解版本、事项历史、旧版只读记录、`imageFiles` 图片及 `chatFiles` 原始文件。附件逐个流式写出，状态快照与对话历史保存附件引用。图片经 sharp 完整解码和重新编码，清除 EXIF 等附加元数据。运行代理时，相关交谈、资料、记忆及本轮使用的图片和文件摘录会发送给配置的模型服务。

`contextState`额外包含完整的个人记忆账本与旧核心归档、后台回顾决定及投递回执、每次请求选中的记忆版本和程序计算的时间；这些诊断不包含完整模型提示词或隐藏推理。后台静默决定不生成消息或任务卡。已确认的别名用于识别群聊指向，群内本人发言仍只是观察资料，不能授予榫执行许可。记忆编辑窗口保留打开时的版本，其他地方更新后须重新打开核对，避免覆盖新内容。

实时状态只携带有限的一页记忆；记忆面板按本人理解、代理方法分别分页加载，旧条目可继续查看和纠正，不随每次聊天流重复推送。JSON导出仍包含全部条目及账本版本。

初版只展示今日及每轮输入、输出、合计token，不估算金额，也不按金额停止运行。仅记录供应商实际报告的用量；缺失、部分报告或中断明确标注，不以字符数推算token。原价格和费用预算路径已移除，旧SQLite历史数据保留，旧配置不会重置模型连接。单轮步数、输出上限、超时和任务许可仍生效。服务只监听本机；服务端测试入口另由HTTPS及密码保护，启停保留用户设置。

纯本机执行的新回合单独显示“未调用模型”，不将当天统计误标为缺失。首次模型请求前会持久记录待结算调用并清除此状态；异常或崩溃后的真实用量缺失仍保留为未知。无法证明未调用模型的旧记录不自动改为零调用。

默认工具支持场景证据、本人理解、方法学习、简短内部状态、本人交流、提醒、任务提案和当前明确委托登记；配置Hub联网连接后增加带来源的检索摘要。获准任务可准备文本，或在另有文件授权的独立Git工作树处理TXT/Markdown/JSON；prepared仍待验收。Windows 客户端登录后自动连接，可在本机或网页对话里指定在线电脑，查询明确给出的目录。榫把明确委托中的设备、目录、筛选条件与条数登记为一次原生任务，无需重复批准；范围不明确时先询问或提出任务卡。不靠固定话术或临时 shell 脚本取得执行权。本人手工委托的精确程序命令仍使用按次文件范围和 MXC 隔离。媒体暂不与任意程序命令组合；浏览器操作、任意桌面控制、安装工具、微信写入、日历及系统推送尚未接入，能力成长目前指知识/方法的积累和使用。

旧代理循环与旧议程/记忆编辑接口已退役；旧数据仍可导出，旧写接口返回410。目录停用后，后续模型请求会跳过能追溯到该来源的原生资料回合及工具结果。归档、已发布的聊天正文和已保存的衍生内容继续保留。完整资料遗忘尚未接通。

## 试用评价

评价它是否减少重复解释和同类误解、能否在相关情境使用正确理解、主动交互时机是否合适、能否从获准实践中改进方法，以及这些变化是否值得所消耗的token。验收允许没有任何开发任务或交付文件。

### 核对方法在下一次是否有用

1. 先定一个能从实际回应或成果独立核对的标准，例如“第一行能直接看出决定”。用同一标准评价两次独立、可比较的对话回复或获准任务成果。第一次偏离时写明原因，再给出相关的新问题或新任务。第二次沿用标准，避免在题目中重复提示要检验的方法。
2. 导出完整 JSON，找出方法的 key 和两次评价的 feedback ID。在源码目录运行下面的命令。原样保留未改善的样本以及缺少评价或上下文的情况。

```sh
npm run compare:method -- "<导出.json>" "<方法key>" "<原反馈ID>" "<后续反馈ID>"
```

比较在本机只读运行，输出记录标识、两次本人评价、请求清单记录的方法版本及供应商报告的用量，省略私有正文。两次任务均有可核验的结果回执时，单独列出唯一同名检查的各自结果。旧导出可回查记忆账本中已有的结果快照，证据缺失时标为不可用。保存成功等检查仅说明各自回执中的条件。没有逐次模型上下文清单的原生任务暂不能核对此项。

若要检验方法本身的影响，可在隔离数据中按相同模型、设置、资料和判据安排两组，其中一组提供该方法，另一组省略。先在不知道分组时评价成果，再核对请求记录和用量。重复多组并记录反例，真实推理另行明确授权。单对样本能显示一次变化，持续效果需要更多可比结果。
