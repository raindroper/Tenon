# 个人成长与任务许可运行时

当前实现依据[README产品契约](../README.md#当前产品契约)：理解本人和能力进化并重。资料是了解背景和学习的输入，不是需要持续优化的项目清单。没有任务和交付物也可以完成有效的成长回合。

2026-11-07 的[内核升级](kernel-upgrade-2026-11-07.md)接入了明确委托统一登记、场景交流与任务执行分离和持久结果交接。源码中一套 Mastra Workflow 负责后台 dispatch / deliver / complete；设备和媒体保存真实操作事实，TaskExecutor 负责新任务的结果转换。部署状态与源码能力分开核对。

## 模型连接与选择

0.1.25 在同一 RuntimeApi 内提供模型连接管理。`Store.models` 保存多个自定义 API 连接和独立 SIWC 注册，`ModelSelection` 是完整的连接 ID、模型 ID、思考配置与可选输出上限。全局默认保存完整选择；后台默认和场景设置保存 `inherit-global` 或 `explicit`，不复制全局值，也不逐字段跨连接继承。全局、后台与场景写入分别核对配置版本，旧 `/api/settings` 模型字段写入已退役。

本人消息在受理时固化场景有效选择，任务登记继承来源回合或相应场景选择。自主后台分析使用后台默认，否则继承全局；当前回合附带的 Observer／Reflector 沿用该回合连接。`growth` 同时覆盖本人交流和自主回顾，不能仅按 mode 判断模型。已经开始或排队的本人回合、工具往返、续写和任务恢复读取原 `ModelBinding`，配置变化用于新回合，不在每个步骤重新读取可变全局默认。

连接配置版本、账号身份版本和凭据版本分别核对。正常 token 轮换不改变绑定；换地址、换账号或更新 API key 的身份版本后，旧运行不能静默沿用新凭据。两个场景可并发使用不同 SIWC 注册，没有进程级的唯一 activeAccount。每次请求仍执行原租约、取消、来源和任务许可检查。

`server/models/provider.ts` 通过统一工厂创建 Mastra 的 `LanguageModelV4`；已有 Codex 项目执行继续走任务范围内的 Responses 中继。SIWC 使用公共 Responses 接口，强制 `store:false`、`stream:true`，重建完整输入历史并按协议规范化指令与工具。SIWC 不接受的输出上限等参数不伪装成已生效；模型目录与思考档位按连接隔离。输出成功以实际终止事件为准，收到部分文本不等于完成。

SIWC 登录、续期和退出属于连接管理，不产生模型任务或开启推理。远程首次授权由新版 Windows 客户端接收本机回调，一次性 code 通过当前 AR 本人会话交给后端；后端持有 PKCE 校验、账号注册、受保护 token 和刷新所有权。普通远程网页目前不提供独立回调完成能力。浏览器状态、原生项目执行器及子进程不接收 token，也不复用用户的 Codex CLI auth 缓存。

`recentDiagnostic` 保存连接最近的脱敏故障，区分用量、网络、模型、权限、凭据和协议问题。目录读取、改名和 token 刷新不等于模型成功，不据此清除故障；真实完成的模型响应才能清除相应诊断。登录状态与故障分别投影，某连接的错误不能阻塞其他有效连接。没有自动换账号、跨模型回退或静默切换计费来源。

模型配置及登录交互见[使用指南](user-guide.md#模型连接与默认配置)，详细契约见[多连接方案](model-connections-2026-11-14.md)。离线测试验证协议、隔离和恢复机制；真实账号授权由本人完成，实际模型与工具能力需在明确授权的范围内验收。

## 一条运行链，两种工具范围

所有模型调用继续由同一个Mastra运行时负责。普通交谈、学习回顾和提醒走growth；只有本人明确许可的持久`task.execute`事件能走execution。没有新增第二套Agent框架、数据库服务或执行平台。

| 回合 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| growth | 授权证据查找、本人理解、方法积累、内部摘要、交流、规划、日常提醒、必要任务提案 | 生成独立交付物、读写工作区、安装工具、自批任务 |
| execution | 在本次不可变任务spec和能力范围内产出 | 换目标、扩大文件范围、追加任务、冒充已完成质量验收 |

场景沿用既有 Case/Thread、`/api/cases` 和 `caseId`，原 ID、消息、来源及任务归属保留。主对话 `personal-growth` 在页面显示为“通用”，原创建意图保持可恢复。普通聊天可新建场景并编辑名称与可留空的背景。新建请求携带稳定的 `requestId`，复用原生线程的创建意图校验，响应丢失后重试返回原场景，不覆盖之后的编辑；同一编号更换创建内容返回 409。委托默认关联当前可用场景，首次在通用场景提交委托由同一运行时物化默认记录。引用回复继承原场景，未新增模型分流调用。

本人聊天只开放一个 `recall` 工具，替换原 `search_chat_history` 和 Mastra 默认回查入口。`mode=search` 将关键词命中和经核验的语义候选合并，默认查当前场景。`scope=all` 从同一主人的场景目录确定可查范围。工具从公开消息表重读本人原话，核对事件归属、消息 ID、当前消息的时间锚点和退役证据，再返回最多五条摘录。结果包含场景标题、原消息 ID 及命中类型，至多补两条同场景的较新原话供核对变化。`mode=messages` 仅允许按本轮已经返回的消息 ID 和偏移继续读，并重新检查权限及有效性。每轮最多三次回查。尚无对应事件的旧本人消息可通过逐字匹配回查，有可核验事件的本人消息才可作为语义候选。

助手回答、工具结果、附件、连接器资料和内部工作状态由各自的对话或资料入口处理。回查得到的历史只为本轮提供背景，上一轮含回查结果的原生回合从后续模型请求副本中跳过。原 `open_related_case`、自动派生任务 journal 写路径和旧 director 循环已移除，历史数据保留。

普通交流的语义仍由模型判断。硬边界控制实际交付物/工作区工具和模型执行入口，不把自然语言内容分类宣称为形式化证明。模型仍需在少量真实相处中校准。

## 许可与授权分别负责什么

模型可以提出仅描述范围的提案，不能自己批准。提案只有目标、缘由、交付说明和能力，没有先行制作的任务正文。批准之前没有执行outbox、执行模型或交付物工具。

本人可批准/拒绝提案，或从`POST /api/tasks`明确委托。普通`/api/messages`不接受批准字段，也不依关键词猜测许可；同一对话模型通过`request_task`承接当前清楚委托，服务端核验当前owner-chat消息并将范围与原事件绑定。文本、有效工作区范围、媒体、原生目录查询使用同一登记路径，目录查询可组合文本交付。`request_media`、`request_local_file_lookup`及其专用授权writer已移除。能力询问、资料里的要求、代理建议和已有访问权限不构成任务许可。

媒体许可仍进入同一协调器，在当前进程直接调用Hub现有生成接口，不另跑执行模型或分类器。提交前持久保存`mediaJobs`，已接收的视频任务由普通程序查询状态、保存结果，轮询不经LLM；提交状态不确定时不自动重复生成。产物保存到私有`media/`，通过本人会话保护的内容接口预览和下载；任务提交成功不等于产物已经完成。不修改Hub源码，也不新增常驻服务。

媒体能力参数由前后端共用`mediaModelError`按真实目录验证，包含自适应比例与声音开关；始终有声模型不能承接明确静音要求。模型切换会清除不兼容的尺寸参数。确定的格式/大小/编码错误终止并保留原任务引用，网络故障仅重取原产物。当前Hub v1.10.8使用秒级共享视频文件名，因此复用现有事件队列：前一个视频保存为本地私有文件后才提交下一个，聊天与其他事项继续调度；提交未知仍需核对Hub，不保证上游未受理。

许可spec不可变，批准/撤销使用revision CAS。唯一执行事件与批准意图在同一SQLite提交，独立连接投递幂等恢复；伪造payload不足以进入执行。`requirementsRevision`与授权版本分开，本人补充原话保存在`requirementUpdates`，不能借修改要求改变原始文件/设备/媒体参数。每个版本的task thread独立，旧结果只能作为实际操作事实，不能完成新要求。原许可可随同一任务安全暂停重开；已撤销许可不能恢复，已确认原操作的迟到结果可以仅补齐事实，不能重做操作。

前台保留场景顺序与并发额度，后台使用独立执行额度，原协调器内联任务分支已替换。Workflow与场景记忆共用原Mastra和libSQL存储；禁用框架无条件自动恢复，按原期限、已用步数、操作回执及当前许可决定恢复。已开始模型且存在实际进展的中断不自动重放；明确暂停且尚无正文/工具活动的回合可在原预算内从持久挂起点恢复。任务历史随场景详情和完整导出保存。

### 跨来源与跨场景接续

`TaskContext`只引用已有事件，核验原`sourceId/sourceCaseId/sourceGeneration`和当前授权，不复制或重新归属资料。本人当前对话可显式选择来源场景查询，关联ID必须来自本轮已找到的资料或原任务已有引用；任务执行只读原场景和这些具体引用，不能由一个链接获得邻近资料的读取权。`find_case_evidence/read_event`沿用原工具入口，原生prompt的来源过滤在每次模型请求前复核。

`list_tasks`跨场景查找须提供关键词；当前消息只可接续已找到的任务。`requirementUpdates.caseId`保存本人续接的来源场景，原任务ID、执行归属、批准范围和执行事件保持。界面从原记录投影续接任务卡，按该场景的补充时间分页；没有第二份任务或消息副本。`read_task_result`提供真实结果及长文本分页，拒绝其他任务或旧要求版本的产物替换。

`TaskRecord.evidenceRefs`保存委托关联的具体资料，`Run.evidenceEventIds`保存执行工具实际返回的资料依赖；后者不能省略，否则无预声明引用的同场景任务会从派生结果绕过来源撤回。结果读取和学习均复核两者。来源撤回按具体来源/连接代次排空跨场景依赖任务，并保持其他独立来源的任务可用。已发布内容留在归档，但失效来源的结果、反馈及方法不会重新进入后续模型上下文。

工作区任务还须持有同主题有效`WorkspaceGrant`，任务绑定该许可版本与完整精确文件清单。批准前及每个工具调用前复核；真实仓库和独立worktree路径在页面展示。授予文件权限不批准某个任务，批准任务也不授予新文件或账号权限。

工作树身份校验统一使用 Git 的绝对管理目录查询和双向注册指针，兼容已验证的 Linux Git 2.34.1 与 Windows Git 2.50，不依赖 `worktree list --porcelain -z` 或旧版不转义路径的文本列表。保留原基准 HEAD、仓库设备/inode、detached、非符号链接及授权版本校验，拒绝 locked/initializing、损坏或失效注册。路径只去掉 Git 输出末尾的一个 LF，保留真实空白；注册文件按严格 UTF-8 读取且不吞 BOM，并检查原始路径实际存在。先前失败的准备意图仍保留，修复后可在同一工作树和原基线恢复，不重建或删除原始证据。

每次provider请求前检查运行时租约、取消信号及执行任务的许可和文件范围。已移除单价、金额估算、费用预留、预算暂停及任务金额上限，不预建多角色/多bot/多模型计费平台。

`UsageTracker`只负责真实token和待返回调用：请求前持久保存pending计数，返回时把输入/输出用量与pending清除在同一行提交。`reported/partial/unknown`标明报告完整性；中断或重启丢失报告时标unknown，不补造token，不重复累计。今日汇总按本人时区及运行开始日期统计，并保留不完整提示。运行视图不输出旧金额字段，旧SQLite历史金额保留且不参与控制；旧任务在读取时投影为无费用spec，旧委托/提案仍幂等。本人发起的对话和新委托默认没有总步数上限，既有任务恢复沿用已保存的有限步数。被动回顾和对话记忆整理有界。输出上限配置和单次请求超时继续生效。

终态更新前先中断并排空已经开始的原生工具。撤回任务、撤销文件权和关闭服务也等待相关工作完成，旧结果不能恢复许可。人工改个人理解仍保持原运行/暂停意图。

## 被动观察、学习时机与提醒

目录、上传文本与连接器变化先本地记录，采集过程保留每条事件的回顾归属。统一 source_review 队列按来源合并，普通来源默认五分钟，微信保留本人配置的间隔。每批至多二十条，剩余资料继续公平排队，失败批次保留原覆盖与预算；无新资料时等待。旧每日全局闸门和微信独立调度表已由同一队列替换，迁移档案保留于原事件库 checkpoint。

批次合并、原事件本地确认及时间任务发出与Inbox共事务，避免跨连接写锁和中断丢批次。停用来源或替换代次后，旧批次不进入另一个主题。失效来源积压不能阻挡后面的有效观察。`processed`表示事件已处理/记录，不单独证明模型学到了东西。

每次供应商请求前重新核对原生历史中的来源引用。失效的目录事件、证据搜索和原文读取结果连同其所在的历史回合从请求副本排除，事件和原生历史仍可导出。已公开正文和此前保存的衍生内容保留。Mastra 日志禁用原始异常载荷，运行时记录安全的错误类别和状态。

模型可安排有具体目的的时间：带提醒正文时，到点由普通程序投递本地消息，0额外模型调用；不带正文时才成为届时需思考的学习回访。每条独立ID，同主题多个提醒不覆盖；可查询/取消尚未到期的提醒。投递先保存消息再确认事件，重启不重复。

恢复推理与主动回顾使用不同命令。回访可安排本地提醒，后续推理须有新的输入。停止主题时，尚未到期与已到期但待处理的安排一并关闭。主题消息写入、任务许可提交和主题停止在同一个主题的写入队列中核对。远程校验跨过一次停止时，即使主题已经恢复，也需要重新提交许可。

暂停推理不暂停已排本地提醒，尚未到期的学习模型和执行仍等待恢复。后端必须运行且机器清醒才能准时投递，当前不代表系统通知或手机送达；逾期提醒的完整时效策略尚未完成。停止主题会取消其提醒和任务，停止目录采集是独立动作。

## 两类成长记忆

原生resource核心继续是唯一记忆存储，thread隔离主题现场。`subject=owner`描述本人，`subject=agent`描述代理方法，旧条目缺subject默认owner。两者不能用相同key互相覆盖。

场景版继续使用这份个人核心。每轮从保留版本投影最多八条适用的明确更正或撤回状态，并与现行记忆一起提供。本人缩小记忆范围后，原先适用的场景收到不含新值的 `out_of_scope` 提示，未曾适用的场景不收到该提示。学习写入在同一个共享队列内复核全部已保存条目，同一主体、原事件和逐字摘录已被本人更正或撤回时，跨键重学也拒绝。精简的 `personal.retirements` 与原条目同库持久化，独立于八版可恢复历史，按证据原场景或原适用范围生效，不进入模型及公开条目。旧库读取不写迁移；下次相关记忆写入会保存仍可推导的依据，升级前已经裁掉的依据无法补回。新事件、其他摘录及其他主体按各自证据判断，同义改写和既存别名仍需后续核对。场景入口和回查沿用同一 RuntimeApi。

本人理解只能来自真实本人表达/反馈文字。方法可来自本人教导、当前主题授权资料，或本人实际评价过的回应片段。最后一种使用服务端提交时保存的目标快照，证据绑定评分、目标ID及完整快照hash，即使comment为空也可学习。它只是方法假设，不能冒充本人原话、个人偏好、明确教导或客观成功，也不能直接做correction升级。单独的模型输出、工具自述和草稿仍不能自证成长。

`TaskLearning`从真实终态run、交付物和现有操作记录组装不可变`task.outcome`证据；先在原Run写入来源journal，再保存并本地结清事件。证据可引用设备、媒体、GitHub、EWS 和本地项目的实际回执。项目命令从当前要求版本的原生事件提取退出码，保留失败和缺少回执的情况。Exchange 接受提交只证明提交被接受。证据不附带邮件正文、GitHub 写入内容或项目命令输出。此事件不进入推理队列，重开补齐也不调用模型。`PersonalMemory`仍是唯一方法记忆writer，引用时保存任务/要求版本与具体检查范围，普通学习保持hypothesis。本人反馈的`taskOutcome`引用及目标hash只由服务器生成。

原始来源失效时，历史反馈保留可验证的旧journal引用用于访问限制；缺少可核验journal的任务目标明确标记不可用，不能降级成无来源评分。新反馈原文仍保存，不对不可用目标重复触发推理。当前内核数据版本为`kernel.schemaVersion=4`，RuntimeApi 命令合同保持一个；客户端兼容相同投影字段的版本3/4，拒绝未知版本。升级保留旧migration记录，旧二进制回滚仍须配套备份。

两类条目均保留范围、有效期、版本与撤回抑制。`PersonalMemory`是唯一策略writer，应用事件库的`rae_personal_memory_versions`保存不可变版本，heads仅指向版本；Mastra继续保存线程、OM和向量。旧resource JSON在原值、最多八个原有历史版本及退役证据无损导入后冻结归档，不再双写、回退，也不自动升级等级或扩大范围。新增版本永久进入账本，界面保留最近八个可操作历史，完整版本可导出；不再有64键生命周期上限。

现行上下文在每次实际模型请求前统一组装，本人身份、交流要求、其他事实和代理方法分别选取，保留等级、范围、版本和完整度。遗漏引用可通过`read_personal_memory`在当前范围读取全文。来源回顾最多读取八条核验过且仍有效的近期本人原话，补充尚未形成长期记忆的交流背景。执行许可仍以当前有效委托为准。明确的本人身份声明可形成来源绑定、无默认过期的身份事实，推断有有限的有效期。泛用纠正改变别名值时撤去不再相符的结构化旧别名，防止隐形旧身份残留。

本人事实和代理方法优先使用本轮对话、引用、授权资料摘要或任务要求匹配的有效条目。简短且有指代的追问可借用同场景更早的核验原话辅助检索。预算装不下相关组时，沿用本机已准备的 BGE 嵌入合并文字与语义匹配，每个检索背景最多计算一个查询向量和 16 条新向量。冷启动分批覆盖适用条目，进程内有界缓存可重建。每次实际注入仍按账本重查版本、证据和范围。缺少本机权重或局部嵌入失败时继续使用文字匹配。相似度只用于排序，事实和方法的有效性仍看各自的证据。

设置、纠正、撤回和恢复经相同策略入口绑定当前本人消息或持久本人操作；API操作先记录已处理的`owner.memory`审计事件，不唤醒模型。预计版本不符返回409。外部文字、被评价的助手内容与代理自己的输出不能冒充本人声明或已验证方法。

实时understanding最多100条，并附understandingPage计数与下一页。记忆面板按subject使用SQL分页，旧条目编辑携带实际读到的entry快照和预计版本；翻页状态不写回实时全局列表，subject切换或关闭取消旧请求，晚返回不能污染新页。完整导出仍读取全部条目与不可变版本，分页不意味着删除或遗忘。

方法被记住及在另一个主题中使用，是当前能力积累的程序基础，不证明通用能力或长期人格已验证。源码自改、安装工具和完整代码沙箱尚未接入，即使本人允许也不能虚报已具备这些执行器。

### 场景观察与语义回查

`SceneMemory` 继续使用现有线程、原生 Memory 和 libSQL。只有实际本人聊天进入 `CaseMemory.runCase` 时才调用 `om.observe({ force: false })`，由 Mastra 检查该场景是否达到观察阈值。后台步数设置少于三时跳过观察且不推进观察游标。同步 Observer、Reflector 及其精炼沿用独立的记忆整理额度，与本人回复共用模型连接和实际用量记录。任务执行、资料来源回顾和其他事件不触发这条观察路径。

同一回合复用原始记录快照，来源与更正策略仍逐次核对。原生 Observer 负责新观察索引；只有反思换代或实际语义回查发现索引缺口时才补写，无增量的普通回复不重写向量。同场景派生写通过已有 PQueue 串行，回查不等待其他场景的模型回合。搜索先核验字面与语义结果、去重交错合并，再限制五条，避免字面命中占满后漏掉跨场景更新。

`beforeObservation` 按原生消息查找已持久化的 `owner-chat` 事件，核对场景、授权、事件及原消息 ID，再从 Store 重读本人纯文本。助手建议、工具回执、引用片段、附件和外部资料由其他路径处理。Observer 与 Reflector 输出的观察组保留原生范围，并加上由服务端生成的来源策略指纹。更正、撤回或范围收窄使指纹变化时，Rae 清除该场景失效的派生观察与向量索引，可随后按当前允许的原话重建。原始消息、公开历史和个人记忆版本继续可追溯。对于没有关联证据事件的直接编辑，按旧值逐字匹配识别受影响内容，无法确定同义改写是否指向同一事实。

回复模型使用公开的输入步骤处理器，仅注入经过当前来源策略核验的观察组，并保留必要的近期未观察消息。回复回合关闭自动 OM，通过观察组本身投影背景，避免原生格式化器同时带入未经组范围验证的当前任务提示和其他提取内容。旧回放中已退役证据所在的轮次会从模型请求副本中跳过，当前本人输入和保存的原始历史继续保留。观察摘要用于补充背景，现行事实与任务许可仍由个人记忆、原事件和许可记录负责。

语义候选使用 Mastra 原生观察向量和本机 `@mastra/fastembed` 1.3.6。`BAAI/bge-small-zh-v1.5` 在同一进程内输出 512 维向量，原生分段按约 320 字符预算处理，发现模型窗口截断则拒绝该嵌入。通过 `npm run prepare:memory-model` 显式准备并校验约 95 MB 的模型文件。默认目录为数据目录下的 `models/bge-small-zh-v1.5`，可用 `RAE_EMBEDDING_MODEL_DIR` 指定，运行时只加载已准备的固定权重。语义匹配结果只作为回查候选，返回前按 `recall` 的同一条校验链复核，命中分数不证明内容仍为最新。

## 数据与入口

联网工具保持单一HTTP路径：`HubWebTools`调用现有Hub的`/v1/responses`及其本地联网工具，不导入Hub内部模块、不改Hub源码、不增加守护进程。迁移后的 Hub 服务连接独立保留地址、模型和凭据，`RAE_HUB_SEARCH_URL`仅与该服务连接的 Responses 地址核对；不跟随全局、后台或场景模型变化，也不向 Hub 发送 SIWC token。不匹配或无密钥时不发请求，也不产生辅助模型pending。只对实际请求通过现有`UsageTracker.trackUnknown`记录pending与未知内部用量；Hub最终轮数字不当作内部完整统计。

`web_search`只返回带真实引用的`gateway_summary`：同时观察搜索调用和最终`url_citation`，普通Markdown链接不算搜索成功。Hub可在内部抓网页，但当前接口不提供可独立确认的原文，所以不暴露假装原文的web_fetch工具。摘要以external/untrusted记录到同一事项Inbox，`ingestProcessed`原子插入并确认，不让查询结果变成下一轮待执行事件。摘要可用于当前回答和来源追溯，不能直接充当本人表达或独立方法学习资料；已有真实反馈学习路径保持。

模型正常返回但触及长度/步数上限，与供应商异常分开处理：`run-outcome.ts`分类，`Run.stopReason`记录`output_limit`或`step_limit`。成长回合保留标注未完成的部分正文，并查询既有Inbox获取真实时间安排回执；执行回合仍失败，不完成任务许可。`maxOutputTokens=null`默认不传输出额度、采用接口默认值；自定义 API 可在完整模型选择中设置适用上限，SIWC 必须保持 null。

`CaseMemory.runCase`统一走原生Mastra.stream，旧generate代理路径已删除。只转交text-delta，逐步保存原生线程；取消订阅时同时中止并排空原生处理，不能只关闭读端。本人交流的正文和notify_user共用`RunResponse`记录，250ms合并持久化、首段立即保存；complete/incomplete/streaming与说明放在独立字段，不改写模型正文。完成、异常、暂停均最终刷盘，已保存正文不会因重试被覆盖。推理及工具参数不进入公开回复。

来源回顾不暴露自由文本通知、场景工作状态writer或立即可见的提案工具。它通过一次`finish_review`提交silent/observe/notify/needs_input/propose，引用实际暴露证据、本人的来源绑定关联及结构化改变。决定、议题投影和outbox在事件库同事务保存；公开正文由RunResponse按稳定ID保存。提案通过原TaskConsent writer幂等创建，跨连接用outbox回执结清，不虚称跨库原子提交。投递前同步核对全部来源及本人事实/近期原话指纹，和已接受变更屏障确定先后；同ID错误正文隔离，崩溃后只补本地回执，不调用模型。静默无消息或卡片；observe保存持续事项而不发消息。事项包含事实、本人关系、帮助机会、必需输入及期限，ready帮助通过proposal登记。新信息可安排原growth_wakes中的一次定时回顾，到期回顾不能续排。提案前可以使用同一套只读连接器工具调研，回执以agent身份保存，写操作仍由本人许可进入任务执行器。真实群内本人发言不能成为任务许可。

微信回顾带同会话有界前文、稳定会话ID、来源代次、发送/接收时间和分片完整度；正文与发送人搜索范围分别说明。关系解释保留为带出处的判断，原生字段缺失不补造。当前时间、当地日期/星期/偏移由同一请求事实函数生成，actor处理器与原生Observer/Reflector模型包装共同调用，清单区分角色；工具与跨场景TaskContext复用EvidenceTime，未知发送时间为null。本地日查询由程序换成半开UTC区间。时间不写入原生历史，既有消息来源的时间投影仍可保留。每次请求的版本/时间清单只作诊断，完整清单随contextState导出。

`maxOutputContinuations`为0或1、默认1。非空公开回答因length结束时可在原线程续写一次，沿用原取消信号和已有的有限步数。续写的tools为空，toolChoice=none。被动学习不自动续写。用量仍经同一meter记录，Run.continuations只记录次数。

异常或暂停已有公开正文或工具活动时停止自动重放；超时即使没有正文也终止，不能重新排队刷新五分钟。Run记录工具启动计数以识别未知副作用；重启先隔离已有进展的事件，再更新Run状态，跨库中途退出不能绕过隔离。旧streaming消息转为incomplete，原文保留。撤销主题/文件权限先撤销许可，再排空已经接受的工作，保留明确的revoked状态。

尚可重试的瞬时失败将下一次可用时间写入事件库的 `events.retry_at` 列，启动时自动为旧库补列。冷却保留受影响主题的处理顺序，其他主题仍可调度。旧的全局 `v2.retryAfter` 元数据作为历史保留，调度只读取事件上的时间。

`reasoning.ts`按已经固定的模型选择生成 `Run.reasoning`，记录请求强度、来源、原因及策略版本。旧 DeepSeek 配置迁移保留 auto 及原固定档位；auto 对实质问题、指代追问、学习和获准任务请求 high，仅无历史、无引用或附件的新会话独立寒暄请求 low。其他协议通过对应适配器映射已支持参数，`default` 表示服务商默认，不与 auto 或全局继承混用。没有额外模型分类，不依据外部资料选择参数，不引入空闲轮询。更高强度不改变权限、步数、用量记录或超时，也不证明上游采纳或答案正确。新的客户端选择持久保存到场景；旧消息的 `reasoningEffort` 继续读取，旧 HTTP 单次覆盖只接受原 auto／none／low／high／max 范围。

`POST /api/events/:id/retry`仅接受显式恢复失败的本人消息，复用同一事件/事项/原始证据/尝试次数与图片，拒绝任务、系统、已处理、已排队及停止主题，不隐式开启推理。`wakeReceipts`从既有时间安排表按case和originEvent读取，不另建回执真源。恢复上下文携带已保存安排避免重复；原消息旁的失败原因与恢复按钮按消息ID和事项匹配，不把历史失败只留成全局红灯。状态快照增加可选`messageId`关联，原事件正文不暴露到摘要。

模型连接修复不会自动重排失败事件。本人明确重试时，原绑定为空的消息可在当前场景解析连接；原 API 连接只修复密钥、地址与协议不变时，可记录一次凭据修复后的新绑定。上述调整都拒绝已经受理工具操作的回合，持久记录原绑定与重试原因。其他已保存绑定继续沿用，不借重试把旧任务换到当前默认账号。

聊天图片沿用同一owner.message事件与事项线程，不新增资料处理或代理框架。消息持有`ImageAttachment`元数据，`rae.sqlite.message_images`持有二进制，两者同一事务写入；恢复事件只引用元数据，轮询快照不含Base64。`server/v2/images.ts`复用sharp解码/重编码，拒绝伪造、损坏、动画及过大图片，去除EXIF等元数据；解码并发1、排队有界。HTTP仅放宽消息体至2MiB，其他JSON接口仍512KiB；图片GET/HEAD经既有入口鉴权、同源策略、nosniff及no-store保护。

Mastra原生历史保存`rae-image:<id>`，`image-context.ts`在原生`processLLMRequest`中仅对供应商副本解析，并逐张核对事项范围；没有外部URL抓取或另一份可写记忆。支持原生跟进、重启及引用旧消息；每次最多4图/1MiB，优先当前与引用的图片，其余明确标注本轮未看到。已关闭原生UnsupportedFileHandler的丢图重试，其余稳定性处理保留；确定的图片400/415/422错误终止该事件、保留原图并提示切换/检查，不反复付费试错。图片及其中的文字仍是资料，不自动成为本人明确陈述或任务授权。

图片草稿由`client/state/image-drafts.ts`持有，按主题隔离，与服务快照无双重所有权；解码、压缩和Blob URL释放由独立小模块负责。发送成功只清理本次提交的图片，期间新增内容保留。流式导出逐张读取图片并等待响应背压，断连停止读取后续附件。取消/暂停在模型和工具排空后继续等待已接受的本人写入，避免异步解码在暂停回执后才落库；两个等待阶段分开，避免本人纠正本身等待模型排空时形成循环。

前端采用方案一的单列对话，旧双侧栏和覆盖样式已移除。`state/useRuntime.ts`是唯一服务快照源，实时连接替换周期轮询，并负责读请求竞争与同操作去重；`state/ui-state.ts`用互斥Panel联合状态统一主题/引用和面板所有权。`components/Conversation.tsx`拥有按主题的未发送草稿和对话内许可；`panels/`按设置、记忆、资料、历史、运行、委托与反馈拆分，通过同一原生dialog按需挂载，次级模块延迟加载。共享ActionMenu和dialog统一Escape、入口焦点恢复及错误定位，没有引入新状态库或前端依赖。异步保存不能关闭后来打开的面板；accepted写入后刷新失败不会诱导重复提交。桌面/窄屏和隔离真实链路验收见[design-qa.md](../design-qa.md)。

Node 24.22.1+，项目脚本可选择已校验本地运行时。`npm ci`、`npm run build`、`npm start`后访问`http://127.0.0.1:4317/`。新安装默认暂停，已有实例保留本人启停设置；密钥在Windows由DPAPI保存。

- `rae.sqlite`：设置、模型连接与默认／场景选择、消息、上传文本、反馈、实际模型用量、成果及持久`mediaJobs`。run带growth/execution，成果和媒体任务带taskId。

| `/api/models/oauth/start`、`/api/models/oauth/:id`、`/api/models/oauth/:id/complete` | 发起、查看、取消或完成本人登录；真实 token 由后端保存 |
| `/api/models/connections/:id/catalog,test,logout` | 分别读取目录、本人明确发起一次模型测试、退出该连接；不是自动切换或自动推理入口 |
| `GET /api/history/runs`、`GET /api/history/events` | 同一 RuntimeApi 的历史分页；可传 caseId、before，每页固定40条，返回 items、nextBefore |
| `GET /api/state?caseId=…&before=…` 与 `/api/state/stream` 同参数 | 当前主题最多40条公开消息，省略游标读取最新页，使用 `conversation.nextBefore` 翻查旧页 |
| `GET /api/cases/:id/images` | 当前主题最近12张聊天参考图的元数据，包含消息窗口以外的图片 |
| `POST /api/messages` | 普通交流，支持caseId/replyTo；明确媒体制作请求经来源绑定登记许可，不接受伪造批准字段 |
| `GET/POST/PATCH /api/cases...` | 关注主题与上下文管理 |
| `GET/PATCH/DELETE /api/personal-memory...` | 理解/方法查看、纠正、撤回；restore按revision恢复为新版本 |
| `GET/POST /api/tasks` | 查看任务，或本人明确范围的委托（requestId幂等） |
| `POST /api/tasks/:id/approve,reject,revoke` | 本人决定，body含revision；实际URL分别用对应动作名 |
| `/api/sources/workspace...` | 目录授权/停止；不等于完整遗忘 |
| `/api/workspaces...` | 文件授权/撤销及真实handoff；不等于任务许可 |
| `/api/media/models`、`/api/media/:id/content,cancel` | 只读媒体模型目录、私有产物预览下载及停止任务；生成仍须有效许可 |
| `GET /api/export` | 当前数据、历史与旧记录只读导出，不含密钥 |

`/api/v2/...`只作同函数URL别名，旧V1编辑410。远端使用`RAE_AUTH_FILE`启用单用户会话认证，并保留Host/Origin限制；不宣称是多用户权限系统或OS沙箱。

## 迁移与验证

运行时只保留一条生产执行路径。旧记录以只读归档或显式导出的方式保留；数据版本、迁移 journal 和回滚要求见[内核契约](kernel-upgrade-2026-11-07.md)。

核心改动运行完整测试、类型检查及构建。使用隔离临时数据和模拟供应商回归授权、来源、用量、取消、故障恢复与导出；不依赖维护者的实际账户、设备或生产数据。部署记录与私人验收产物在仓库之外维护，发布流程见[部署说明](deployment.md)。
