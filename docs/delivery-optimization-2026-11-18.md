# 检查复用与统一交付验收

2026 年 11 月 18 日更新。范围为榫的通用检查和文件交付，业务 Skill 继续作为原始测试输入。

## 已实现的行为

- 文件检查绑定其实际涉及的成果、断言和报告依赖。增加无关说明文件时，原检查可以复用。受检内容、检查条件、依赖或任务要求版本变化时重新检查。命令、桌面操作和外部状态检查继续实际执行。
- 校验报告和原始输入可以作为明确引用的只读验证依赖。程序检查它们的实际路径、内容和哈希，完成前再次核对。它们独立于最终成果清单。
- Windows 任务在主会话及已接受工作结束、成果核验通过后，按清单保存准确的文件快照。服务端沿原设备通道接收、核对并发布文件。原始输入、辅助程序及未选文件不因目录中存在就进入本批最终交付。
- 传输不完整时，任务保留领取入口。重试使用同一快照和已有分片，成功后提供单文件及 ZIP 下载。下载、打包和重试均由程序处理。
- 服务器历史归档领取继续沿原快照模式。新的辅助验证依赖路径从归档发布清单中排除，历史已交付记录保留。

## 执行流程

本人委托进入榫后，任务及权限交给本机 Codex。Codex 读取资料、生成业务成果，并提交成果清单与检查方法。程序完成检查，复用仍有效的文件回执，冻结通过核验的最终文件，接收分片并核对 SHA-256，最后发布文件与 ZIP 下载入口并完成任务。

发现业务检查失败时，问题返回当前执行会话修正。文件传输失败时，按原快照继续领取。要求变化和许可撤销会阻止不匹配结果发布。

## 真实模型场景

全部使用 gpt-6.1-sol、max、Codex 0.169.0，在独立工作区和独立数据存储中执行。模型通过已有原生账号的测试连接运行；执行、验收、冻结、传输、保存与 ZIP 使用生产类。自动任务收尾和本人 HTTP 下载入口另有完整离线集成验收。

| 场景 | 实际过程 | 本地执行至完成回执 | 结果 |
| --- | --- | --- | --- |
| 对账表格 | 读合成账目，区分已入账与待入账，生成 CSV 与 JSON，实际运行校验，保存两份成果 | 新开任务约 143 秒 | 11 项独立检查通过，错误计入待入账款的样本被拒绝 |
| CSV 代码修复 | 先复现原实现失败，修改解析器，运行测试，提交实现及验证证据，保存代码文件 | 新开任务约 240 秒 | 19 项独立断言通过，原错误实现被拒绝 |
| 库存交接报告 | 读合成事实，生成 Markdown 与 JSON，核对事实、日期及未确认信息，保存两份报告 | 新开任务约 120 秒 | 19 项独立检查通过，错误日期与虚构已确认信息被拒绝 |

这三类小产物的本地发布耗时约 14～27 毫秒，生成 ZIP 约 1～4 毫秒。该数值只描述隔离环境下的程序阶段。模型执行时间仍包括读资料、生成内容和实际工具操作，尚未据此确定生产链路的稳定提速比例。

首轮对账实验的测试连接发生重试，随后测试适配器遗漏空阶段审核投影，又进行了原会话续做。这些记录保留供核查。最终表格采用修正测试适配器后新开任务的时间。CSV 与报告场景运行于先前候选；验收暴露的校验报告登记问题已在后续代码修正，原始提交回放通过，新开对账任务也在首轮提交通过。

## 复用与故障验证

在相同对账文件上，0.1.33 的检查器收到新增说明文件后的请求时，产生两条新的检查生命周期记录。修改后的检查器保留原检查回执，新增记录为零。将受检金额从 10,601 改为 10,600 时，两版都重新检查并拒绝错误值。

两份原先因临时报告未登记为成果而失败的真实提交，已使用原校验程序和实际产物副本回放，首轮检查通过。临时报告进入验证依赖，最终 ZIP 仍只包含选定成果。篡改校验报告后，完成检查被阻止。

实际文件及 HTTP 验收还覆盖断传、丢失确认、源文件在冻结后被修改、快照篡改、链接逃逸、设备和授权撤销、主任务完成前尚未发布、设备离线后下载、服务重启后下载，以及下载不触发模型或原生任务重跑。

源码全量自动检查通过：1,343 项测试全部通过，类型检查和生产前端构建通过。四组 HTTP 文件验收分别覆盖 Windows / Linux 与正常传输 / 确认丢失。

实际 Windows 发布包另通过 36 项测试，使用安装包中的 JavaScript 和原生运行时；Linux 候选通过 48 项按平台选择的测试，以及原生执行与持久工作区两组生产隔离验收。Linux 首次验收误选 Windows 绝对路径样本后，修正了测试选择器，并复用同一候选镜像重新验收；对应 Windows 样本全部在 Windows 包中执行。
