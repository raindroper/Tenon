# Windows 与服务端项目执行

2026 年 11 月 17 日实跑发现的结单权限、运行组件和 Windows 执行问题，以及性能调查的原始记录，见[执行调查](harness-followup-2026-11-17.md)。

Rae 使用一个生产 Mastra 运行时承接交流、本人理解、资料连接和任务许可。项目工作作为同一个任务执行器中的原生操作，交给 Windows 客户端或服务端 Linux 执行设备的 Codex app-server 0.169.0。两种设备共用任务派发、授权核对和回执协议。代码搜索、修改、命令、原生会话、工具循环与上下文处理由上游执行引擎负责。

## 场景、任务与目录

| 概念 | 负责内容 | 与目录的关系 |
| --- | --- | --- |
| 场景 | 交流、背景资料与本人理解 | 不绑定目录，不保存默认工作目录 |
| 委托 | 本次完整目标、原话、交付要求、补充要求和许可 | 需要命令或文件操作时，选择设备与执行范围 |
| 工作区 | 本次执行使用的实际目录与身份 | Windows 可使用本人指定目录。服务端为每项任务分配独立的临时工作区 |

同一场景可以处理多个项目，也可以始终只交流。一个项目可以供不同场景中的明确委托使用。已使用的项目目录只是方便再次选择的历史记录，不是持续执行权。

执行位置采用两条默认规则：操作已有项目、本机文件或本机应用使用项目所在客户端；远程文档观察、收信、持久化、提醒及不依赖本机环境的文本处理留在服务端。聊天所在设备不等于项目所在设备。本人当前明确选择优先；否则从同一场景已批准的项目任务中参考位置，没有已确认位置且只登记一个客户端时默认选择它。多个候选或缺少真实目录时一次询问。纯文本代码片段和远程差异评审不要求启动本机执行。

设备目录列出离线及协议未就绪的客户端，明确委托可以先保存并等待该设备恢复或更新。可用性不改变任务位置，也不会因只剩服务器在线而选择服务器。独立临时项目或服务端实验需来自本次明确选择，服务端资源仍由原任务卡确认。旧任务沿用已有设备、工作区、授权、期限和原生会话，不按新默认重新选址。没有增加项目注册表、分类模型、另一套调度器或迁移执行器。

任务完成后释放执行会话。Windows 保留项目文件、临时工作区和原生会话供回查，下一项委托重新确定目录与授权。Windows 任务需要继续预览时可保留开发服务，停止环境或退出客户端时清理并确认排空。Linux 的临时工作区在任务结束后释放，已保存的操作、文本、差异与结果回执可从原任务查看。

同一设备上相同或嵌套的项目目录只在写入会冲突时排队，独立目录和共用目录的只读任务仍可并行。服务端根据已知路径排队，客户端再按实际目录核对连接点等别名。保留预览的原任务继续占用工作区，停止预览、归档所属场景或撤销设备时，收到实际排空回执后才释放。退出状态未知时保留原占用和结果供核对。

## 执行路径与权限

在对话中明确委托「让记事本另存一份测试文件，核对内容并把截图发回来」或「在后台把 Clash Verge 切到日志页并截图」时，选择在线且支持 Windows 应用操作的设备。Rae 把指定应用和截图回传要求登记进同一任务许可。记事本使用任务临时目录中的测试文档和新的 TXT 文件名，提交后核对实际文件内容。Clash Verge 需已打开主窗口，支持查看首页及日志并核对页面标题。已获准回传的截图作为原对话的私有附件，和实际执行报告一起查看。

Windows 应用工具使用内置 Cua Driver 0.49.1 的后台控件操作。部分应用控件可能自行改变焦点，工具会报告观测到的变化。截图仅捕获目标窗口，遇到不支持的窗口状态会报告缺失。Windows 应用任务使用独立临时工作区。网页端到端测试使用现有的 Playwright 流程，当选中的 Windows 设备可以运行项目预览时自动提供浏览器工具，访问范围是本次任务启动的本机预览。需要截图时在委托中提出，Rae 会将已核验的截图附在原对话中。

清楚的本人委托通过同一个 `request_task` / `TaskConsent` 合约登记完整目标。本人可在输入框选择设备，也可在对话中说明执行位置。未指定时，Rae 根据文件位置、所需工具和网络出口选择设备。目标离线时显示实际状态，执行位置需要由本人重新选择。

Linux 任务登记后等待本人在任务卡确认。任务卡显示服务器、临时工作区、读写与联网范围、CPU、内存、临时磁盘和进程数上限，以及临时文件保留期限。确认只对卡片上这一次任务生效。更换设备或执行资源需要重新登记和确认。Linux 支持隔离的命令、临时文件和测试流程，项目预览仍在 Windows 客户端提供。

Windows 默认允许为本任务读取本机文件与依赖、写入所选工作区及任务临时目录，并允许命令联网。本人可选项目读取、只读项目或关闭命令联网。严格项目读取可能限制需要检查祖先目录或额外依赖的工具链。新增目录、网络权限或目标通过本人明确委托重新确定范围。Linux 命令只接触任务临时工作区和执行环境所需工具，公网访问取决于已批准的网络范围。

Windows 的网络开关控制本机命令联网，并启用或停用项目预览。浏览器是独立的预览能力，HTTP 和 WebSocket 经任务代理访问内置执行进程树拥有的本机监听地址。代理核对实际监听端口的进程归属，拦截外部地址、其他进程的本机端口及跨来源跳转。Edge 沿用自身沙箱和独立浏览器上下文。浏览器工具只开放预览所需操作，文件产物落在任务独有目录，项目需要这些文件时由原沙箱命令在已许可的写入范围内复制。浏览器文件上传及宿主代码执行工具停用。模型通信和既有资料连接沿用各自的连接许可。

Hub 网关、Rae 的 HTTP 入口与 Codex 本机模型转发通道均不额外设置请求体字节上限。上游接口及具体业务字段、图片和邮件附件的有效性规则继续生效。实际传输仍受可用内存、磁盘及单次请求超时约束。没有因此修改 Hub 程序、认证、账号或模型计费方式。

客户端使用上游 Windows MXC 权限配置限制文件写入，启动回合前核对引擎返回的实际权限配置和审批策略。受信任的钩子在工具调用前检查当前许可、要求版本、设备和目录身份，每次模型及资料调用也经过同一授权边界。项目配置保持 untrusted。原生命令和文件审批不能触发脱离沙箱的重跑，回合内权限扩张和持久执行规则修改也被禁用。模型中继凭证留在执行器进程，Shell 子进程的环境不会收到该凭证。[Codex App Server 审批](https://developers.openai.com/codex/app-server#approvals) · [Shell 环境设置](https://learn.chatgpt.com/docs/config-file/config-advanced#shell-environment-policy)

内置执行器使用严格配置校验，并关闭原生插件与推荐目录同步，避免任务之外的后台 Git 下载留下子进程。插件安装不由原生执行器自行触发。取消和关闭仍须确认原生进程及已接受操作实际排空。

权限配置控制的是程序能接触的文件和网络。任务选择真实目录写入时，目录内的覆盖和删除仍是该进程可实施的写操作。允许命令联网时，命令或项目服务可能产生外部效果。需隔离真实文件的工作可用任务临时目录，或使用现有的授权工作树准备改动。真实邮件、GitHub 写入等已接入业务动作由各自的精确任务许可和操作回执约束。生产数据、付费或账号变更需要可核验实际对象和效果的专用执行入口。

新任务没有默认总时长截止。新委托的本地项目由内置 Codex 完成，记录的 `stepLimit` 为 `null`，并可手动停止。v2 项目保留首响应等待和显式请求硬限，流停滞使用原生执行器的超时。已捕获 v1 协议的任务沿用原请求时限。历史有限步数、截止时间和用量在补充、断线与恢复后继续生效。仅保存供应商实际 token，缺失或部分报告保持显式状态。

## Rae 与原生会话的分工

上下文承接、原始附件交接、执行方案与实际检查回执沿同一任务流处理，见[项目执行契约](project-execution-contract.md)。

- TaskConsent 和原执行事件拥有委托与授权事实；Codex 会话不创建另一份任务许可。
- 执行设备持有原生会话和工作区，Rae 运行时保存有序、可去重的工具、文本、差异、问题及结果回执。
- 当前主会话汇总分工结果，并负责提交交付、阶段审核和向本人提问。最终提交保存实际检查。完成还需主回合正常结束、分工和已接受操作收尾，以及复核当前交付。
- 受理时已明确的必需最终文件随任务要求保存，最终核验按实际文件、件数和内容检查回执匹配。未明确的格式和业务规则由当前任务、适用 Skill 和实际验收依据确定。
- 设备收到的确认只代表回执已持久保存。重传按操作和序号核对已保存的摘要，原样重传直接确认。任务结果更新通过原回执的任务标识排队，周期检查补齐未完成的本地更新，进程重启时从持久记录核对。
- 本人原话、当前适用记忆、原始图片和关联资料进入任务；腾讯文档、邮件、GitHub 等沿用已有授权和只读资料工具，查询结果保留原出处。
- 模型密钥保留在服务端；客户端引擎只获得本任务的本机临时访问令牌。模型仍使用 Rae 已配置的连接。
- 已升级的执行设备获得任务所绑定模型的上下文窗口，由 Codex 按其原生阈值自动压缩并继续当前会话。窗口来自该连接的模型目录，或本人对该模型 ID 填写的实际窗口。旧目录可重新获取，未知窗口保持为空。摘要请求仍经原任务的授权、超时和用量记录，内部摘要只回给原生会话，不进入任务正文。
- 模型转发以完整的 Responses SSE 事件为边界。响应流在终止事件前断开时，向 Codex 返回明确的流式失败，保留已收到的正文和实际用量，并在原模型回执记录故障类型。原生执行终态仍由设备回执确认。
- 补充要求送入原会话；停止先关闭接收，再中断原生回合、清理该任务所有已加载会话的后台终端，确认进程退出。未确认时显示未知，不能宣称已停止。
- 正常暂停保存原工作并在授权仍有效时恢复。无法确认原生进程状态时保留未知和原工作区占用。后续全局暂停继续等待正在处理的操作；历史上已结算为未知的记录仍保留供核对。晚到的真实退出和排空回执可以补齐原结果、释放目录，不能恢复撤回的许可。

## 客户端与迁移

Windows x64 安装包包含固定版本的 Codex app-server、Node 24.22.1/npm、rg 和 Playwright MCP 0.0.85，并保留上游许可证。构建阶段按固定摘要验证这些随包分发的引擎依赖。浏览器使用本机 Edge，其他语言运行时和 Git 使用本机安装。新项目执行需要支持固定沙箱策略和限定预览的客户端能力。旧任务与回执继续可查，更新客户端后可发起新项目委托。

项目命令优先使用本人已有且在本次读取范围内的 PATH；内置 Node 作为后备工具，不覆盖已有开发环境。许可钩子和 Playwright 仍通过绝对路径使用固定 Node。首次执行及等待后续做时，原执行器按项目版本声明、锁文件和脚本核对实际工具路径、版本、依赖和必要后端连通性。缺少匹配环境时说明并等待，不擅自安装系统组件、扩大读取范围或迁到服务器。环境变量继续使用既有白名单，不把宿主全部凭据传给任务。

手工填写单个程序及 JSON 参数的任务表单由工作区委托入口替换。历史精确命令回执和必要的兼容处理保留，简单目录查询仍有独立原生入口。当前服务端内核数据版本为 9，v2 项目执行需要设备声明 `local_project_contract_v2_1`。未升级的设备上的任务保留原选择并等待更新。历史任务沿原许可和捕获协议处理。完整导出包含项目原始回执，工作区索引和界面摘要均为读取投影。回滚使用匹配版本的应用和数据备份。

## 验证范围

原生离线联调使用真实固定版本引擎、实际 Windows 文件与命令、真实 Edge/Playwright 浏览器和父子进程。模型响应在这些回归中固定，用来验证协议和执行机制，不代表真实模型效果评测。覆盖代码修改、保留本人修改、禁止越界写入、资料工具、浏览器交互与截图、预览保留与进程排空，以及暂停恢复、要求更新、日志去重、迟到结果和实际用量记录。

原生执行器的集成边界与验证方法见[集成评估](../research/harness-integration-evaluation-2026-11-12.md)。协议回归不能作为所有工具链或真实模型能力的证明。

## 兼容边界

0.169.0 的实际 CMD 回归已覆盖引号、中文、空格和带点路径，Node 与绝对路径 Python 正常执行。当前主机的 PowerShell 5.1 与 PowerShell 7 在 MXC 中仍出现注册表访问错误。任务启动时通过原生环境接口和同一权限配置实际检测 Shell，并把可用 CMD 及失败原因作为环境事实传入执行会话。[PowerShell/MXC 问题](https://github.com/openai/codex/issues/55613)
